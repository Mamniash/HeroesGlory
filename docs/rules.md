# Heroes & Glory — правила (техническая выжимка)

Источник: «Heroes Glory», 2-я редакция, Офиздат, 2025.
Документ описывает **механику** для реализации в Foundry VTT.
Художественные тексты, описания рас и лор сюда не входят — они берутся из книги при наполнении компендиумов.

> **Правило для агента:** ничего не додумывать. Если механики нет в этом файле — спросить, а не изобретать по аналогии с D&D.

---

## 1. Кубики

Используются только **d6** и **d20**. Других костей в системе нет.

## 2. Герой

### 2.1. Первичные навыки

| Навык | Сокр. | Назначение |
|---|---|---|
| Атака | А | шанс поразить противника |
| Защита | З | шанс избежать поражения |
| Сила Магии | СМ | сила заклинаний, длительность эффектов |
| Знания | Зн | объём Маны |

**Мана = Знания × 10.**
Модифицируется навыком Интеллект: базовый ×12, продвинутый ×14, эксперт ×15.
Специализация «Интеллект» (10 ур.): +50 к максимуму Маны.

### 2.2. Прочие параметры

| Параметр | Источник | Диапазон |
|---|---|---|
| Здоровье (ОЗ) | раса + класс | — |
| Скорость | раса | — |
| Зрение | раса | обычное / в темноте / ночное / слеповидение |
| Удача | 0 при создании | −3 … +3 |
| Боевой дух | 0 по умолчанию | целое |
| Уровень | старт 0 | 0 … 20+ |
| Опыт | старт 0 | — |
| Золото | старт 2d6 × 10 | — |

**Удача:** позволяет перебросить любой кубик в любой проверке. Отрицательное значение даёт Рассказчику право перебросить кубик игрока. Использование снимает 1 единицу, значение стремится к 0.

В реализации переброс за Удачу автоматизирован только для кубов броска атаки (d6 попадания
и d20 поражения, независимо друг от друга) и проверки навыка (d20) — кубы эпик-каскада
(таблица/существенность/локация) переброс не затрагивают, но если сам куб попадания
переброшен и результат меняет попадание на эпик (или наоборот), каскад для попадания
перебрасывается заново. Кнопка переброса лежит прямо на карточке в чате рядом с
результатом нужного кубика — видимость (владельцу при положительной Удаче, только
Рассказчику при отрицательной) пересчитывается у каждого клиента отдельно.

**Удача и Боевой дух как сумма (реализация).** В `system.luck`/`system.morale` хранится
только ручная поправка Ведущего (по умолчанию 0). Итог считается в `prepareDerivedData`:
навык (Удача / Лидерство, §3) + раса (Минотавр, §2.3) + поправка + эффекты (артефакты);
Удача ограничена ±3, Боевой дух — нет (§11). Переброс за Удачу сдвигает поправку так,
чтобы на 1 к нулю сдвинулся **итог** (`spendLuck`, rolls.mjs). Потраченная Удача к базе сама
не возвращается — Ведущий правит поправку. Ведущему в режиме редактирования клик по иконке
Удачи или Боевого духа открывает окно в стиле системы (`HeroesGloryDialog`, `#editCorrection` в
hero-sheet.mjs): вся разбивка, нулевые части тоже (навык, раса у Боевого духа, ручная поправка,
эффекты, итог, пометка об ограничении Удачи) и поле поправки — целое число со знаком или без
(`parseCorrectionInput`, rolls.mjs); OK или Enter сохраняет, Отмена или Esc — без изменений. Новых
пределов нет: итог Удачи ограничивается ±3 там же, где считается, Боевой дух — без предела. Вне
режима редактирования и у игрока клики как раньше (Удача — подсказка, Боевой дух — тест). Ещё
поправку меняют отдых (Удача → 0) и конец боя (Боевой дух → 0). Разбивка — и в подсказке иконки.

**Золото (реализация).** На листе героя — в свободной полосе слева от ячейки специализации: иконка
золота с полосы ресурсов HOMM3 (`SMALRES`, кадр 6, `assets/smalres/`) и число; видят все, кто
видит лист. Ведущий меняет его быстрым полем, как Здоровье у существа (§9): «150» — поставить,
«−30» / «+20» — изменить, не ниже 0 (`parseGoldInput`, rolls.mjs); Enter или уход из поля. У
игрока — только число. Клик по монетам — подсказка «Золото», Ведущему в ней же — как вводить.

**Иконки листа героя (реализация).** Маленькие иконки в ячейках — первичные навыки, Опыт, Мана
(`pskil42`), вторичные навыки (`secskill`), Боевой дух (`imrl42`), Удача (`ilck42`) — показываются
не из исходных кадров HOMM3, а из их версий, увеличенных xBRZ ×4 с повтором краёв (`--pad`, иначе
xBRZ делает углы полупрозрачными): `assets/<набор>-x4/`, имена файлов те же. Ячейка на листе
меньше файла, браузер уменьшает его со сглаживанием: `image-rendering: auto` задано только картинкам
из папок `-x4` (`src/scss/components/_hd-icons.scss`), весь остальной лист — `pixelated`, как
раньше. Исходники в `assets/` не меняются. Пути — `skill-icons.mjs`, поэтому новые иконки и в окне
повышения уровня, и у специализации. Большие иконки подсказок (`pskill`, `secsk82`, `imrl82`,
`ilck82`) прежние.
Здоровье — своя иконка, не кадр HOMM3 (среди первичных навыков HOMM3 её нет): стеклянное сердце с
game-icons.net (`lorc-glass-heart.svg`, автор Lorc, CC BY 3.0,
https://game-icons.net/1x1/lorc/glass-heart.html), оформлено как Скорость и Зрение — золотой
градиент, чёрная обводка (`assets/game-icons/`, `healthIconPath` в skill-icons.mjs); в ячейке с полем
2 px кожи, в подсказке — тот же SVG. Авторы иконок game-icons — `assets/weapons/README.md`.
В HOMM3 Удача −3…0 нарисована одним кадром (череп, подкова, слиток). Для −1, −2, −3 — свои кадры:
подковы кадров +1, +2, +3, перевёрнутые вниз; фон и рамка кадра на месте, тень построена заново.
Исходники — `assets/ilck42-neg/` (из них же собраны кадры −3…−1 в `ilck42-x4`) и для подсказки
`assets/ilck82-neg/`; Удача 0…+3 — прежние кадры.
Пересобрать: сначала `python scripts/build_luck_negative.py` (Pillow, numpy), затем
`scripts/upscale_icons.py --hero-sheet` — его нужно запускать Python 3.9 с пакетом `xbrz.py`
(готовое колесо есть только для 3.9; как поставить — в шапке скрипта).

**Боевой дух:** после боя восстанавливается до базы (§11): сброс пишет 0 в поправку.

В реализации тест Боевого духа бросается с листа (а не из трекера боя). У героя — клик по
иконке Боевого духа вне режима редактирования: при положительном значении владелец бросает
тест на повтор хода (d6, 4+), при отрицательном тест на пропуск хода (1–3 — пропуск) бросает
только Ведущий; у игрока клик ничего не делает, без оставшихся попыток — тоже. Подсказка
иконки (как у Скорости) показывает «Попыток осталось: N из M». У существа — кнопка «Боевой дух»
на его листе, в том же смысле (§9). Кто и какой тест может бросить — `moraleCheckVariant`
(rolls.mjs). Карточка теста — видимость как у атак (§10). Счётчик использованных попыток за
бой хранится во flags актёра и сбрасывается по хуку `deleteCombat` (момент завершения боя —
удаление документа Combat); у героя там же обнуляется поправка Боевого духа.

### 2.7. Создание героя (реализация)

Книга, стр. 16–18. Новый герой стоит на уровне 0 — «не создан»: «Уровень 0» в ячейке уровня
затемнён тем же стилем, что невыбранные раса, фракция и класс. Вне режима редактирования
владелец или Ведущий кликает по ячейке — открывается обычный пикер уровня; без расы, фракции
или класса — уведомление «Сначала выберите: раса, фракция, класс» (только недостающее). Клик
по заблокированному классу до фракции — «Сначала выберите: фракция».

Подтверждение уровня 1 и выше у несозданного героя — это создание (`grantCreation`,
`module/helpers/hero-creation-flow.mjs`; решения — чистые функции
`module/helpers/hero-creation.mjs`). Сразу выдаётся всё, где нет выбора (ниже), Здоровье и Мана
полные, создание помечено завершённым, карточка с бросками — шёпотом владельцам и Ведущему. Затем
опыт ставится в порог выбранного уровня, повышения идут обычным окном через «Опыт». Повышения
до выбранного уровня записываются в `system.creation.levelUps`, после каждого Здоровье и Мана
снова полные; повышения сверх него, в игре, — по обычному правилу. После создания пикер уровня
вне режима редактирования не открывается — только Ведущему в режиме редактирования, как раньше.
Герои выше 0 без завершённого создания (созданные до этого) считаются созданными, ничего не
получают (`isHeroCreated`).

- **Второй вторичный навык (стр. 16):** d20 по списку §3, строка 20 — по фракции, как при
  повышении уровня (Некрополис — Некромантия, остальные — Лечение). Совпал с базовым навыком
  класса — тот становится продвинутым, второго навыка нет.
- **Книга Магии (стр. 17):** пустая, в слот 10 — Волшебнику, Алхимику и тем, кому случайный d20
  дал Мудрость. Заклинания на выбор не выдаются (§11): игрок добавляет их вручную из компендиума.
- **Джинн (стр. 11):** выбора нет — выдаётся сам: книги на старте нет — Книга Магии и
  «Волшебная Стрела», есть — «Молния». Элементаль Воздуха по-прежнему получает «Полёт» при выборе
  расы.
- **Оружие (стр. 17):** стандартное по классу: «Оружие воина» (урон 5) или «Оружие волшебника»
  (урон 3) — колющее/рубящее, эпик-таблица клинкового оружия (стр. 41), слот 1; название игрок
  правит на листе предмета. Стрелковое оружие стрелку не выдаётся (§11).
- **Куда кладётся выданное:** Книга Магии — слот 10, оружие — слот 1, артефакт надевается, если
  его слот свободен, иначе — в рюкзак (стр. 18: «Все, что не надето на Героя, находится в его
  инвентаре»).
- **Золото (стр. 18):** 2d6 × 10, прибавляется к имеющемуся.
- **Артефакт (стр. 18):** d6 — тип, затем 2d6 — строка таблицы (стр. 46–51). В пяти таблицах
  строк 2–11: выпавшее 12 перебрасывается. Мощные артефакты на старте — по книге, без
  ограничений. Строка таблицы записана у книжных записей компендиума
  (`flags.heroes-glory.tableRow`); «Доспех/Щит (N уровень)» в бросок не входят.

Всё выданное помечено флагом `creationGrant`. **После создания** смена расы или класса ничего из
этого не снимает и не выдаёт заново: диалог смены перечисляет выданное (предметы, золото,
навык, поднятый совпадением). Ведущему — «Сбросить создание» в меню «…», только после
завершения: удаляет помеченные предметы, откатывает золото на сумму броска (не ниже 0),
возвращает навык, поднятый совпадением, к базовому и откатывает записанные повышения до
выбранного уровня (первичные навыки, +5 ОЗ за Защиту, выданные и поднятые навыки — чистая
функция `resolveCreationRollback`); уровень уменьшается на их число, опыт — как до создания плюс
заработанное сверх порога выбранного уровня (`creationResetExperience`). Повышения сверх
выбранного уровня не откатываются. На уровне 0 герой снова «не создан», следующее создание
бросает заново.

**Базовый навык класса** помечен флагом `classBaseSkill`. При смене класса (или фракции,
меняющей класс) прежний базовый навык снимается, пока он базовый; уже поднятый (совпадением
или повышением уровня) остаётся, Ведущий получает предупреждение в диалоге и уведомлением.

## 3. Вторичные навыки

20 навыков, 3 уровня: **базовый → продвинутый → эксперт**.

Список (бросок d20 при получении):

| d20 | Навык | d20 | Навык |
|---|---|---|---|
| 1 | Нападение | 11 | Магия Воды |
| 2 | Доспехи | 12 | Магия Огня |
| 3 | Стрельба | 13 | Мудрость |
| 4 | Тактика | 14 | Интеллект |
| 5 | Помехи | 15 | Мистицизм |
| 6 | Лидерство | 16 | Волшебство |
| 7 | Удача | 17 | Дипломатия |
| 8 | Поиск пути | 18 | Разведка |
| 9 | Магия Воздуха | 19 | Обучаемость |
| 10 | Магия Земли | 20 | Лечение / Некромантия |

**Старт:** 2 навыка — базовый (от класса) + случайный (d20).
Если выпал уже имеющийся стартовый — он поднимается до продвинутого.

**Лимит:** 8 навыков. С навыком Обучаемость на уровне эксперта — 10.

Эффекты каждого уровня каждого навыка — таблица на стр. 36–39 книги. При наполнении компендиумов переносятся как текст.

Механически значимые (влияют на расчёты):

- **Удача:** базовая Удача = 1 / 2 / 3 по уровню
- **Лидерство:** базовый Боевой дух = 1 / 2 / 3
- **Интеллект:** множитель Маны 12 / 14 / 15 вместо 10
- **Мудрость:** доступ к заклинаниям 3 / 4 / 5 уровня
- **Магия <Стихии>:** базовый — снижает стоимость; продвинутый/эксперт — заклинания школы творятся на соответствующем уровне
- **Тактика:** Скорость в первом раунде +3 / +5 / +7
- **Поиск пути:** эксперт — Скорость навсегда +1

В реализации (`module/helpers/skill-bonuses.mjs`, `actor-hero.mjs`'s `prepareDerivedData`)
считаются Удача, Лидерство, Тактика, Поиск пути (эксперт) и Мудрость; Интеллект и Магия
стихий — как раньше. Уровень навыка — наибольший `tier` среди предметов-навыков с этим
ключом.
- **Скорость:** в `system.speed` хранится база (раса); на листе в обоих режимах — итог: база +
  Поиск пути (эксперт) + эффекты (рана в ногу, артефакты). В режиме редактирования клик по числу
  открывает поле базы, как у первичных навыков.
- **Тактика** в Скорость на листе не входит — только в бросок инициативы через `@tactics`
  (§5.1), в подсказке Скорости строка «В первом раунде».
- **Мудрость:** см. §6.1.

**Лист навыка (реализация).** В стиле героя, как лист заклинания. В шапке — список навыка вместо
поля названия: название и картинка предмета следуют за выбранным навыком (`_preUpdate`,
documents/item.mjs; расчёты везде по ключу `skillKey`, не по названию), тексты всех трёх ступеней
берутся из компендиума «Навыки» по тому же ключу, текущая ступень не меняется; навыка в компендиуме
нет — тексты не трогаются, предупреждение в консоль. Три ступени — тёмные
панели с фаской, текущая — золотой линией; где лист редактируется, клик по другой ступени делает
её текущей. На листе героя левый (вне режима редактирования) и правый клик по навыку открывают его лист: у Ведущего с правкой, у
игрока (в том числе владельца) только для чтения; прежняя подсказка у иконки навыка (название,
ступень, текст текущей ступени) убрана — всё это есть на листе.

## 4. Развитие

### 4.1. Опыт

За побеждённое существо: **X d6 опыта**, где X = уровень существа.
Рассказчик может дать 1d6 (или 2d6) за отыгрыш или продвижение по сюжету.

| Ур. | Опыт | Ур. | Опыт | Ур. | Опыт | Ур. | Опыт |
|---|---|---|---|---|---|---|---|
| 1 | 15 | 6 | 400 | 11 | 1100 | 16 | 2500 |
| 2 | 45 | 7 | 500 | 12 | 1300 | 17 | 2800 |
| 3 | 150 | 8 | 650 | 13 | 1600 | 18 | 3200 |
| 4 | 220 | 9 | 800 | 14 | 1900 | 19 | 3600 |
| 5 | 300 | 10 | 950 | 15 | 2200 | 20 | 4000 |

Свыше 20-го: +500 за уровень.

**Начисление опыта (реализация, §11).** Окно опыта у Ведущего (`experience-award.mjs`):
- по завершении боя (хук `deleteCombat`, только у активного Ведущего) — существа боя с уровнями,
  побеждённые (0 ОЗ, недееспособно, повержено, без сознания) отмечены, остальных Ведущий
  отмечает сам; все герои боя отмечены; бонус Ведущего 0/1/2d6;
- вручную — «Начислить опыт» в меню «…» листа героя (только Ведущий): без существ, только
  бонусные кубы и выбор героев.
Каждый отмеченный герой бросает свой Xd6 за каждое отмеченное существо (уровень 0 — опыта нет)
и бонусные кубы; Обучаемость +1 (базовая, продвинутая) или +2 (эксперт) за каждый куб, включая
бонусные (`experienceAward`, `aptitudeBonusPerDie`, rolls.mjs). Опыт пишется в
`system.experience` героя; существа и актёры бестиария только читаются. Карточка на каждого
героя — шёпотом владельцам и Ведущему, без `rolls`, как у повышения уровня. Токен героя связан
с актёром по умолчанию (`documents/actor.mjs`), поэтому всё, что происходит с героем в бою,
остаётся на его листе.

### 4.2. Повышение уровня

При новом уровне: **+1 первичный навык и +1 вторичный навык.**

**Первичный** — случайно, бросок d20 по таблице класса (стр. 22). Диапазоны свои у каждого класса. Пример (Рыцарь): 1–6 → А, 7–14 → З, 15–17 → СМ, 18–20 → Зн.

**Если повысилась Защита — герой получает +5 ОЗ.**

**Вторичный** — бросок d20 по списку. Если навык уже есть — переброс. Волшебник может без броска взять Мудрость, если её нет. Затем выбор: поднять любой имеющийся навык на ступень **или** изучить выпавший новый.

### 4.3. Специализация (с 10-го уровня)

Требует уровня эксперта в навыке либо владения заклинанием. Список — стр. 23.

Книга, стр. 23: «Достигнув 10-го уровня, Герой может получить дополнительную специализацию. Вам
нужно быть Экспертом в навыке, чтобы взять специализацию, или владеть заклинанием.» Таблица — 12
специализаций: 7 по навыкам (Нападение, Стрельба, Доспехи, Волшебство, Интеллект, Некромантия,
Лечение — нужна экспертная ступень этого навыка) и 5 по заклинаниям (Цепная Молния, Воскрешение,
Ускорение, Стена Огня, Клон — нужно это заклинание). По школам магии специализаций нет.

**Реализация.** Специализация — предмет типа `specialization` (`module/data/item-specialization.mjs`:
`system.key` — ключ навыка или название заклинания из книги, закрытый список 12; `system.description` —
текст книги). Компендиум «Специализации» (`specializations`) открыт игрокам на чтение; специализацию
можно перетащить из него на лист героя. У героя `system.specialization = {type, key}` вычисляется из этого
предмета (`actor-hero.mjs`) и в памяти лежит поверх старого хранимого поля (оно в схеме только для миграции,
ниже), поэтому все расчёты читают его как раньше; в базу вычисленное значение не пишется. Условия —
`module/helpers/specializations.mjs`: уровень 10 и экспертная ступень навыка или заклинание у героя
(`specializationRequirement`). Заклинание узнаётся по записи компендиума, из которой скопировано
(`_stats.compendiumSource`), иначе по названию (`specializationSpellName`) — так же и бонусы
специализаций при касте. Автоматизированы все, кроме Некромантии и Лечения (их применяет Ведущий).

Каждое — ровно в одном месте:

| Что | Где |
|---|---|
| Список 12, ключи, порядок | `SPECIALIZATION_SKILLS` / `SPECIALIZATION_SPELLS`, `specializations.mjs` |
| Название навыка | подпись навыка в `lang/ru.json` (`HEROES_GLORY.SecondarySkill.*`); сборка компендиума и лист читают её через `specializationLabel` |
| Название заклинания | его ключ (название заклинания по книге), `specializations.mjs` |
| Текст книги | `scripts/data/specialization-compendium-data.mjs` → запись компендиума → копия на герое; окно читает индекс компендиума, ячейка — копию героя |
| Иконка | `specializationIconPath` (`skill-icons.mjs`) с `SPECIALIZATION_SPELL_ICON_FRAMES`; картинка записи — её же результат при сборке |
| Условие | `specializationRequirement`, `specializations.mjs` |
| Эффекты, «применяет Ведущий» | функции `specializations.mjs` по ключу |

Название и картинка предмета следуют за ключом (смена ключа на листе предмета переименовывает его,
меняет картинку и берёт текст из компендиума — `documents/item.mjs`); подпись и иконка в ячейке
считаются по ключу, переименование предмета их не меняет.

**«Интеллект» +50 Маны** — изменение `mana.max` «прибавить 50» в финальной фазе эффектов, как у
прежнего сохранённого эффекта, но эффект не хранится: его строит из предмета `allApplicableEffects`
актёра (`documents/actor.mjs`). Ядро применяет изменения одной фазы по приоритету (сначала
умножение, потом прибавка), так что итог тот же, что раньше: Мана = расчёт × множитель артефакта +
50 + прибавки артефактов. В `prepareDerivedData` прибавка попала бы под множитель (тест
`test/specialization-mana.test.mjs`).

**Правила предмета** — для любого способа создать его (перетаскивание, окно, макрос; `_preCreate`,
`_preUpdate`, `_preDelete` в `documents/item.mjs`):
- специализация бывает только у героя;
- у героя не больше одной — для всех, Ведущего тоже: замена сначала удаляет старую, потом создаёт
  новую; не создалась — уведомление Ведущему;
- игрок берёт только одну из 12 с выполненным условием, удалить или изменить её не может — только
  Ведущий;
- если предметов всё же два, действует первый по `sort`, затем по id; в ячейке и подсказке —
  предупреждение; предмет с ключом не из 12 не считается, в консоли — предупреждение с именем героя
  и ключом.

**Перетаскивание на лист героя**: игрок — если у героя ещё нет специализации и условие выполнено,
окно подтверждения со строкой «Сменить специализацию потом сможет только Ведущий»; иначе отказ с
уведомлением («Не хватает: …», «сменить может только Ведущий»). Ведущий — в любом режиме, любую из
12, окно подтверждения: «Заменить «X» на «Y»?», если специализация уже есть, и «Условие не
выполнено» с тем, чего не хватает. На существо специализация не перетаскивается.

**Миграция мира** (`helpers/specialization-migration.mjs`, один раз у активного Ведущего при
запуске, версия — в настройке мира `migrationVersion`): старое хранимое поле `system.specialization`
осталось в схеме только для миграции (в памяти поверх него — вычисленное значение, как у `mana.max`);
у каждого героя — создать предмет из компендиума, убедиться, что он есть, затем удалить старый эффект
«+50 Маны» и старое поле (удаляется только этот ключ, `system` целиком не переписывается — запись
целиком прошла бы через очистку схемой) и поставить флаг. Старый
эффект снимается у всех актёров мира, где он есть. Несвязанные токены героев не трогаются —
перечисляются в шёпоте Ведущему вместе с итогом. Не созданный предмет оставляет старое поле, и
версия не записывается — следующий запуск повторит.

**Ячейка на листе героя** (`apps/specialization-window.mjs`):
- не выбрана и взять нельзя — замок, «недоступна»; клик — наша подсказка: заголовок, правило со
  стр. 23, «Не хватает: …» (уровень, навыки на экспертной ступени — с теми, что у героя ниже эксперта,
  заклинания) и кнопка «Все специализации» — окно для просмотра, без OK;
- не выбрана и взять можно — лавровый венец, «можно выбрать», ячейка подсвечена; клик — та же
  подсказка (сколько доступно), кнопка «Все специализации» — окно выбора;
- выбрана — иконка и название по ключу (ячейка не пустеет); клик по всей ячейке — полное описание:
  текст книги с предмета героя, «Применяет Ведущий вручную» у Некромантии и Лечения, «Книга,
  стр. 23», предупреждение «Условие не выполнено», если оно не выполнено; правый клик — лист
  предмета (у Ведущего с правкой, у игрока только для чтения).

**Лист специализации** — в стиле героя: в шапке список 12 вместо названия, текст книги (правит тот,
кто может править предмет; на герое — только Ведущий), требование, «Применяет Ведущий вручную»,
«Книга, стр. 23»; на герое — «Условие выполнено» или «Условие не выполнено» и «Не хватает: …».

**Окно** — общий диалог системы: текст правила со страницей; слева «Навыки» и «Заклинания» (иконки
в одинаковых клетках, недоступные серые), справа подробности выбранной: текст книги (из индекса
компендиума), требование, «Условие выполнено» или «Не хватает: …», у заклинания, которое герою пока
не сотворить, — «Сотворить пока нельзя: нужна …». Клик по иконке только показывает. Над OK —
«Сменить специализацию потом сможет только Ведущий»; OK создаёт предмет из компендиума, второго
подтверждения нет. Игрок выбирает один раз и только выполненную; Ведущий в режиме редактирования
назначает или меняет любую, в обход условий (с пометкой и тем же предупреждением), и снимает
крестиком (предмет удаляется); в режиме редактирования клик по ячейке сразу открывает окно.
Подсказок по наведению на листе нет — только наши, по клику. Иконки: навык — его экспертная
иконка HOMM3 (`secskill-x4`/`secsk82`, §2.2), заклинание — иконка заклинания (`assets/spells/`), заглушки —
game-icons `lorc-padlock` и `lorc-laurel-crown` (`assets/game-icons/`). Решения — §11.

## 5. Бой

### 5.1. Инициатива

```
Инициатива = d20 + Скорость
```

В реализации формула — `1d20 + @speed + @tactics + @initiativeBonus`: Тактика (§3) даёт
Скорости бонус «в первом раунде боя», и книга прямо говорит, что это «влияет… на ваш бросок
инициативы». У существ `@tactics` = 0. `@initiativeBonus` и отказ от Тактики —
`initiativeRollParts` (rolls.mjs): Минотавр-герой +2 (стр. 12), «Не обнаружил врага» −10 и без
Тактики (стр. 25).

Бросают все участники. Ходят по убыванию. При равенстве — выше Скорость. При равной Скорости — монетка. Порядок сохраняется на все последующие раунды.

**Засада** (стр. 25): не обнаруживший врага до начала боя получает −10 к броску инициативы и не
может использовать вторичный навык **Тактика** (прежняя запись здесь — «вторичные навыки» вообще —
была неточной: книга называет только Тактику). **Реализация:** статус «Не обнаружил врага»
(`hgSurprised`, с HUD токена) Ведущий ставит герою или существу до броска инициативы; снимается в
конце боя (`clearCombatStatesAfterCombat`).

**Вступление в идущий бой** (стр. 25): «Если Существа вступают в бой, который уже идет (то есть
это уже не первый раунд боя), они появляются в начале нового раунда, кидают тест на Инициативу и
ходят согласно правилам»; Тактику не используют, из засады — +10 к инициативе и Тактика.
**Реализация** (решения — §11): участник, добавленный в начатый бой с раунда 2 (`isLateJoin`,
rolls.mjs; хук `preCreateCombatant` → `markLateJoiner`), помечен флагом `joinedRound`; добавленный
в раунде 1 — обычный. Призванные и клоны вступившими не считаются. Бросок инициативы берёт данные
участника, не актёра (`HeroesGloryCombatant#getInitiativeRoll`, `initiativeRollData`,
documents/combat.mjs): вступивший — без Тактики; со статусом «Из засады» (`hgAmbush`, с HUD токена,
ставит Ведущий до броска) — +10 и Тактика (`initiativeRollParts`). «Из засады» и «Не обнаружил
врага» взаимоисключают (`excludeAmbushOrSurprise`); «Из засады» снимается в конце боя. В раунде
вступления ход вступившего пропускается (`HeroesGloryCombat#nextTurn`, `joinerWaits`), со
следующего он ходит по своей инициативе. Скорость для ничьей берётся из тех же данных, что бросок.
Ручная инициатива в трекере — как есть. Бросок, переставивший порядок, ход с текущего участника не
сдвигает: ядро держит ход по номеру, мы передаём номер в новом порядке (`turnKeepingCombatant`,
`HeroesGloryCombat#updateEmbeddedDocuments`). Переброс Эльфа у вступившего — до конца раунда его
появления (`canElfReroll`).

**Минотавр** (стр. 12): «+2 к тесту на инициативу» — у героя-минотавра в формуле (выше). Существ
расовые особенности героев не касаются.

**Эльф** (стр. 9): «При броске Инициативы эльф может перебросить кубик. Примените новый результат
броска, каким бы он ни был.» **Реализация** (`module/helpers/initiative.mjs`): на карточке броска
инициативы героя-эльфа — кнопка «Перебросить (Эльф)», видят владелец и Ведущий; перебрасывается
только d20, остальные слагаемые те же (`elfRerolledInitiative`), инициатива участника
обновляется, в чат — строка «d20 A → B, инициатива X → Y» с той же видимостью, что у карточки.
Один раз на карточку, пока карточка — текущая инициатива участника и бой не дальше первого раунда
(`canElfReroll`).

**Ничья** (стр. 24, трактовка §11). Своя сортировка участников (`HeroesGloryCombat`,
`module/documents/combat.mjs`; сравнение — `compareTurnOrder`, rolls.mjs): выше инициатива; при
равной — выше Скорость, та, что вошла в бросок (у героя — с Тактикой, у «Не обнаружил врага» —
без неё); при равной Скорости — монетка: случайное число, которое участник получает один раз при
добавлении в бой (флаг `coin`, хук `preCreateCombatant`), поэтому порядок между ними весь бой один и
тот же. Участники без инициативы — в конце. Работает и при ручной правке инициативы в трекере.
Скорость для ничьей запоминается при броске инициативы — одного участника, всех, существ
(`HeroesGloryCombat#rollInitiative`, флаг `rolledSpeed`, хук `preUpdateCombatant`,
`rolledSpeedToRecord`); ручная правка инициативы в трекере и переброс Эльфа (меняет только d20)
оставляют записанную, а если её ещё нет — записывают текущую. Скорость, изменённая потом (Ускорение, Замедление, Молитва,
рана в ногу), порядок не меняет — «все участники ходят заново в том же порядке» (стр. 24). У
участника, бросившего до этого исправления, флага нет — сравнивается текущая Скорость (`tieBreakSpeed`).

### 5.2. Действия в раунде

Три действия, комбинируются в любом порядке:

1. **Перемещение** — клеток = Скорость (1 клетка ≈ 5 футов)
2. **Взаимодействие** — достать предмет, открыть дверь, сменить снаряжение
3. **Основное действие** — атака **или** заклинание

Альтернативы основному действию:
- **Бег** — ещё одно Перемещение
- **Расторопность** — ещё одно Взаимодействие
- **Защита** — атакующие получают −2 к тесту на попадание до начала следующего хода героя

**Защита (реализация).** Статус «Защита» (`hgDefending`) — с HUD токена или кнопкой на листе
существа. Длительность задана в самой записи статуса (`duration: 1 turn, expiry turnStart`), ядро
v14 переносит её в эффект при включении любым способом и помечает истёкшим в начале следующего
хода защищающегося; `expireDefending` (combat.mjs) удаляет истёкший эффект. Снимается и по
окончании боя. Точка отсчёта — бой самого защищающегося, а не бой, открытый в трекере: ядро берёт
её из `game.combat`, наш хук `preCreateActiveEffect` (`stampEffectStartFromActorCombat`, combat.mjs)
переставляет её на бой актёра (`actorCombat`, ниже в §6.4). Пока статус есть, любая атака по цели (оружием или естественная, ближняя или
дальняя) получает −2 к d6 попадания (§5.3, §11); заклинания — нет (у каста нет теста попадания).

Модификаторы перемещения:
- вслепую (темнота, туман) — клетка стоит вдвое
- сложная местность — клетка считается за две
- сотворение заклинания — расстояние перемещения вдвое меньше
- стрелковая атака — −1/2 к перемещению

### 5.3. Атака = два теста

#### Тест на попадание (d6)

| d6 | Результат | Множитель урона |
|---|---|---|
| 1 | промах | 0 |
| 2 | промах | 0 |
| 3 | задел | ×0.5 |
| 4 | попал | ×1 |
| 5 | сильно попал | ×2 |
| 6 | эпик-попадание | ×2 + таблица эпика |

Таблица едина для всех существ и героев, от уровня не зависит.

Модификатор: **−1 к тесту, если цель дистанционной атаки на соседней клетке.**

#### Тест на поражение (d20)

```
Успех, если d20 > Защита(цели) − Атака(атакующего)
```

**Если Защита цели ≤ Атаки атакующего — поражение автоматическое, тест не бросается.**

Оба теста можно бросать одновременно (d6 + d20).

**Модификаторы попадания (реализация).** Решение — `resolveHitModifiers` (rolls.mjs): «Защита»
цели −2; стрельба по цели на соседней клетке −1, если у стрелка нет Стрельбы продвинутой ступени
или выше; легендарный атакующий +1. Таблица d6 читается по изменённому результату (`resolveHit`,
§11). Соседство мерит сетка сцены (`tokensAdjacent`, module/helpers/grid.mjs): диагональ —
соседняя клетка, у большого токена проверяется каждая его клетка. Нет токена атакующего на сцене
цели или сцена без сетки — штраф не применяется, в карточке строка «Дистанция до цели не
определена». Модификаторы фиксируются при броске и хранятся во flags карточки; переброс за Удачу
применяет их к новому кубу. В подробностях карточки — строка «Попадание: d6 5 − 2 (Защита цели) = 3».

**Серия атак (реализация, §11).** Размер серии — `attackSeriesCount` (rolls.mjs): существо —
«Кол-во атак» статблока, +1 за «Месть» при неполном здоровье; герой — 1, ближний бой +1 за
Нападение продвинутой ступени или выше, дальний +1 за Стрельбу любой ступени, +1 за
соответствующую специализацию (`system.specialization`, стр. 23). Каждая атака серии — отдельная
карточка с отдельным подтверждением, эпиком и доспехами. После подтверждения Ведущим на карточке
кнопка «Следующая атака (k из N)» (видят владельцы атакующего и Ведущий): та же цель, её
состояние читается заново на момент броска (упавшая первой атакой цель получает ×2 во второй).
Цель без сознания, недееспособна, повержена или с 0 ОЗ — кнопки нет, строка «Серия атак
прервана». Нажимать кнопку не обязательно: серия ничего не блокирует. Карточка находит
атакующего и цель по uuid токена, так что урон несвязанного токена уходит в сам токен.

### 5.4. Эпик-попадания

При 6 на тесте попадания:

1. Урон ×2
2. Небольшая цель (размером с человека) отступает на 1 клетку назад или по диагонали — **даже если тест на поражение провален**. Если путь заблокирован — отступления нет. Если позади обрыв — падает.
3. Бросок d6 по эпик-таблице **оружия** (если бьёт герой) или **существа** (если бьёт существо) — художественное описание удара
4. Повторный бросок d6: при **6** — существенное повреждение, переход к тесту «Куда попал»

**Стрелковые атаки эпик-таблиц не имеют.**

#### Куда попал (d6)

| d6 | Место | Эффект |
|---|---|---|
| 1–2 | нога | −1 к Скорости до излечения |
| 3–4 | рука | роняет предмет |
| 5 | торс | цель падает |
| 6 | голова | цель теряет сознание |

(Детальный вариант с кубиком попадания: 1 правая нога, 2 левая нога, 3 правая рука, 4 левая рука, 5 торс, 6 голова.)

### 5.5. Доспехи

Уровень доспеха гасит последствия эпик-попадания:

| Ур. | Эффект |
|---|---|
| 1 | избежать негативных последствий эпика в защищённой части (кроме урона). Доспех разрушается |
| 2 | то же + урон эпика вдвое меньше. Доспех разрушается |
| 3 | то же + урон эпика снимается полностью. Доспех разрушается |
| 4 | любой урон по защищённой части вдвое меньше. Эпик разрушает доспех |
| 5 | любой урон вдвое меньше. Эпик доспех не разрушает |

Щит даёт **+1…+5 к Защите** в зависимости от уровня.

**Уровни 4-5 в реализации** — сознательное отступление от буквального «по
защищённой части тела» у уровня 4, решение принято и задокументировано
(§11): множитель ×0.5 применяется к любому урону безусловно, без привязки
к зоне, одинаково для 4 и 5 (при строгом прочтении «по защищённой части»
условие срабатывало бы примерно раз на 36 атак — явно не замысел книги).
Несколько надетых доспехов 4-5 уровня одновременно не компаундят
множитель — применяется один раз (`resolveArmorItemMultiplier`,
`module/helpers/rolls.mjs`). Складывается со специализацией Доспехи
мультипликативно (`combineHitAndState`'s третий аргумент).

**Уровни 1-3 в реализации** — подавление последствий «Куда попал»
(решение, что именно подавляется — `resolveLocationConsequenceType`,
`module/helpers/rolls.mjs`, единая функция и для отображения карточки, и
для применения по кнопке подтверждения, см. §5.9) и, для 2-3,
дополнительный множитель урона (`resolveArmorZoneMultiplier`:
0.5 для уровня 2, 0 для уровня 3, 1 для уровня 1 — «кроме урона»).
Привязано к зоне буквально, в отличие от 4-5: доспех гасит эффект/урон
только если он **надет** в слот, соответствующий «Куда попал» (`paperdollSlot`;
голова↔3, торс↔5, нога↔9 — допущение §11; отметки «Куда надевается» на зону не
влияют, §11); для руки слота нет вообще, значит
«роняет предмет» доспехом не гасится никогда — это следует из отсутствия
записи в карте локация→слот, не из отдельного условия-исключения).

**Разрушение — два разных условия, не одно правило на оба случая:**
уровень 4 разрушается на любом эпик-попадании безусловно (тот же отход
от привязки к зоне, что и у его собственной митигации урона); уровни
1-3 разрушаются только если этот конкретный предмет защитил именно этот
удар (книга: «Доспех **при этом** разрушается» — «при этом» отсылает к
факту срабатывания защиты). Уровень 5 не разрушается никогда. Только
строка в чате (`HEROES_GLORY.Roll.ArmorDestroyedPending`/`ArmorDestroyedApplied`,
в будущем/прошедшем времени до/после подтверждения — см. §5.9), предмет не трогаем.

Одновременно надетые доспех 3 уровня (зона совпала) и доспех 5 уровня:
итоговый урон 0 в любом случае (0.5 доспеха-5 × 0 доспеха-3 = 0) — в
карточке чата показывается только строка про доспех 3 уровня, строка
про безусловный доспех 4-5 уровня для этого попадания подавляется —
показывать обе только запутывало бы, раз итог всё равно определяет тройка.

### 5.6. Падение и потеря сознания

- **Упавшая цель:** урон по ней ×2. Встаёт в свой ход, тратя всё Перемещение.
- **Без сознания:** урон ×3, до конца боя неподвижна.

В реализации оба состояния — реальные статусы через `CONFIG.statusEffects` (с иконкой
на токене), а не текст или флаг: их можно и переключить вручную с токен-HUD (для случаев
падения не от эпик-попадания — книга говорит «любая потеря равновесия»), и они
автоматически навешиваются, когда «Куда попал» (§5.4) выпадает на торс/голову. Множитель
урона (×2/×3) считается поверх множителя из d6 попадания — чистая функция
`resolveTargetStateMultiplier` в rolls.mjs; если у цели оба статуса разом (гипотетическая
ситуация, книгой не описанная), урон не перемножается до ×6 — берётся более тяжёлое «без
сознания» (×3). Множитель фиксируется в начале атаки, до применения её же последствий —
попадание в торс/голову той же атакой не задним числом удваивает/утраивает её собственный
урон. Оба состояния снимаются автоматически по завершении боя (`deleteCombat`), как и
Боевой дух (§5.8) — Встаёт-в-свой-ход/тратит-всё-Перемещение не автоматизировано (нет
системы очерёдности действий), только сам факт снятия статуса.

«Куда попал»: нога получает не текст, а настоящий Active Effect (−1 к Скорости, снимается
только вручную — «до излечения» не привязано к концу боя, в отличие от падения/потери
сознания) и складывается, если ранили в ногу повторно. Рука — как и раньше, только строка
в чате, инвентарь не трогается.

### 5.7. Легендарные существа

Отличия:

- **+1 к броску теста на попадание** для легендарного существа
- эпик от легендарного существа даёт существенное повреждение при **4+**, а не при 6
- тест на поражение вместо обычного: `d20 + Атака(нападающего)` против `d20 + Защита(цели)`. Больше — урон нанесён
- при огромной разнице возможны крайние случаи: автоматическое поражение либо принципиальная непробиваемость

**В реализации:** +1 к d6 попадания легендарного атакующего (`resolveHitModifiers`). Встречный
тест — если легендарен атакующий **или** цель: оба d20 бросаются в карточке атакующего,
`resolveContestedDefeat`; строка «Поражение (легендарное): d20 A + Атака = … против d20 B +
Защита = …»; при ничьей урона нет. Крайние случаи получаются сами из разницы Атаки и Защиты.
Порог существенности 4+ (п. 2) — отдельный повторный d6 эпика (`resolveEpicSeverity`), не куб
попадания, поэтому с +1 не складывается: например, легендарное существо выбросило 5 на d6
попадания → 5 + 1 = 6, эпик; затем повторный d6 = 4 → существенное повреждение (у обычного
существа нужно 6).

### 5.8. Боевой дух

**Положительный:** в конце своего хода бросок d6, успех на **4+** → ходит ещё раз. Число попыток за бой = значению Боевого духа.

**Отрицательный:** оппонент (или Рассказчик) объявляет тест перед ходом. На **1–3** цель пропускает ход. Число тестов за бой ограничено значением.

**Минотавры:** получают расовый бонус +1 к Боевому духу (см. §2.3); их
стартовый/минимальный Боевой дух равен 1 даже без навыка Лидерство. Считается
автоматически, вместе с Лидерством (§2.2); `system.morale` — только ручная поправка.

**Существа (реализация).** У существа своё поле `system.morale` (ручная правка, по умолчанию 0 —
в статблоках книги Боевого духа нет) и порог «Дикой морали» `system.moraleThreshold` (§9, §11).
После боя сбрасывается только счётчик попыток, само значение — нет: это не поправка поверх
базы, как у героя, а значение, которое Ведущий задал существу.

### 5.9. Ранения и смерть

- ОЗ ≤ 0 → недееспособен до конца боя
- атака по недееспособному → смерть навсегда, бросок не требуется
- «Воскрешение» временно приводит в чувство
- после боя без помощи: d20, **10 и ниже** — погиб; выше — через час приходит в себя с 1 ОЗ и 1 Маны

**Ранения:** персонаж, ставший недееспособным, записывает Ранение, когда приходит в себя.
Каждое Ранение снижает максимум Здоровья и Маны на 5. Если максимум (Здоровья или Маны)
опустился до 0 — персонаж умер навсегда. Новый уровень снимает одно Ранение. Долгое лечение
или волшебный целебный источник может снять одно или больше Ранений — на усмотрение Ведущего.

В реализации — только ручной счётчик Ранений (`system.wounds`) с кнопками +/− на листе героя;
автоматической записи Ранения при недееспособности и автоматического снятия при новом уровне
нет (прогрессия уровней ещё не автоматизирована — отдельная задача). Штраф от Ранений
вычисляется в `prepareDerivedData()`, **до** бонусов артефактов: сначала из базового значения
(`health.base`, а для Маны — Знания × множитель) вычитается 5 × Ранения, затем поверх этого
накладываются бонусы артефактов через Active Effects в фазе `"final"` — так же, как уже было
устроено для Маны (§8.2), и по той же причине: поле, которое пересчитывает наш собственный
`prepareDerivedData()`, должно получать бонус уже после этого пересчёта, иначе наш же расчёт
его сотрёт. Оба максимума floor'ятся в 0, а не уходят в минус.

**Недееспособен:** тоже реальный статус (§5.6), навешивается автоматически на любое
изменение `system.health.value`, при котором результат ≤ 0 — не привязано к конкретному
источнику урона: срабатывает одинаково и от ручной правки ОЗ на листе, и от автоматического
списания урона после подтверждения атаки (см. «Кнопка подтверждения» ниже) — Foundry вызывает
`_onUpdate` при любом изменении документа, независимо от того, что его вызвало. Атака по
недееспособной цели вообще не бросает кубы: диалог с обязательным подтверждением у
атакующего (действие необратимое), и только после согласия — цель получает статус core'а
«повержен»/DEFEATED (тот самый значок черепа в трекере боя) вместо удаления документа
персонажа: «не стирать чужого персонажа» — про случайный необратимый клик, а не про то, что
нужно физически уничтожать лист.

**Кнопка подтверждения (реализовано):** урон и последствия «Куда попал» (падение/потеря
сознания/−1 к Скорости) от атаки в чате не применяются к цели в момент броска — только после
явного клика Ведущего на карточке. До клика карточка показывает предложенный исход в будущем
времени («цель потеряет сознание», «Доспех защитит от…», «Предложенный урон: N»); строки
самого броска (что выпало на кубике, какой множитель) остаются как факт, без изменений. После
клика те же строки переключаются на прошедшее время, кнопка исчезает и заменяется отметкой
«Применено». Что именно применить — чистая функция (`resolveAttackResolution`,
`module/helpers/rolls.mjs`), общая для отображения карточки и для самого применения, поэтому
показанное и применённое не могут разойтись. Списание Маны при касте заклинания — **не**
гейтится этой кнопкой: игрок тратит собственный ресурс и видит это сразу, аналогия с
`killIncapacitatedTarget`'s готовым диалогом подтверждения не подходит («необратимо меняет
ДРУГОГО актёра» — про мана-трату не так). Защита от повторного применения — флаг `confirmed`
на самом сообщении чата, проверяется первым в обработчике клика; не защищает от двух
одновременных кликов с двух вкладок Ведущего — признано достаточным для стола с одним
Ведущим. Если цель успела удалиться между броском и кликом — явное уведомление
(`ui.notifications.error`), а не тихий no-op. Если карточка брошена, пока по той же цели
висела другая неподтверждённая атака, — у Ведущего на ней предупреждающая строка (не
блокирует подтверждение, просто напоминает, что обе карточки считали множители/доспех от
одного и того же, ещё не изменённого состояния цели). Видна только Ведущему и считается у
него при отрисовке (`hadUnconfirmedAttackBefore`, rolls.mjs, по `timestamp` карточек и
`confirmedAt` подтверждённых), а не при броске у автора: предупреждение нужно только для
решения о подтверждении, а игроку намекало бы на существование приватной атаки Ведущего
(сервер рассылает шёпот всем клиентам, скрывается он только при отрисовке — проверено
живьём). Считаются только карточки того же боя и того же раунда (бой и раунд атакующего
записываются в карточку при броске, `combatRound`); вне боя предупреждения нет, отменённая
карточка его не даёт. Реролл после подтверждения запрещён, кнопки переброса скрываются вместе с
кнопкой подтверждения.

**«Отменить» (реализация, §11).** Рядом с «Подтвердить» на неподтверждённой карточке атаки и
заклинания — кнопка «Отменить», только у Ведущего (`cancelCardByGm`, roll-actions.mjs): для
забытых и ошибочных карточек. Ничего не применяется; у заклинания списанная Мана возвращается
кастующему (кроме карточек урона Стены Огня — они Маны не стоили; `cancelledCardRefund`,
spell-effects.mjs), строка «Мана возвращена: N». Карточка помечается «Отменено
Ведущим», кнопок на ней больше нет (подтверждение, переброс за Удачу); длящееся заклинание
перестаёт занимать место в пределе трёх.

**Цифры над токеном (реализация, §11).** Любое изменение Здоровья — урон, лечение, ручная правка —
даёт над токеном «−N» / «+N», который поднимается и тает (встроенный бегущий текст ядра,
`showHealthPopup`, module/helpers/health-popup.mjs; вызывается из `_onUpdate` актёра на каждом
клиенте, Здоровье до изменения передаётся в опциях обновления). Цвет — по источнику (`damageKind` в
опциях): оружие белый, огонь оранжевый, молния и воздух фиолетовый, лёд и вода голубой, земля
коричневый, заклинание без стихии розовый, прибавка Здоровья всегда зелёная; у заклинания — по стихии
эффекта, иначе по школе (`spellDamageKind`); правка без источника — белая. Видно тем, кто видит токен;
у скрытого токена — никому, и Ведущему тоже. Отключается настройкой ядра «бегущий текст статусов».

«Проверка после боя» — кнопка на листе героя, видна только Ведущему и только пока у героя
статус «недееспособен»: либо бросок d20 (10 и ниже — тот же DEFEATED-статус, без Ранения,
поскольку Ранение положено «когда приходит в себя», а не когда умирает), либо вторая
кнопка «Получил помощь» — тот же результат (1 ОЗ, 1 Маны, +1 Ранение), но без броска.
Межплатформенное ограничение: применение эффектов к цели (авто-статус, послебоевые кнопки)
требует прав владельца на её документ — обычно это Ведущий; если игрокам разрешено
атаковать существ не в их владении, права нужно настраивать отдельно в Foundry, это не
решается кодом системы.

### 5.10. Отдых

Раз в день: сон + плотная еда. Восстанавливает **10 Маны и все ОЗ**.
Без отдыха базовые характеристики на начало дня **делятся вдвое**.

**Отдых (реализация, §11).** «Отдых» в меню «…» листа героя (владелец и Ведущий) и «Отдых всем
героям» в шапке списка актёров (только Ведущий; окно со списком героев, отмечены те, у кого есть
владелец-игрок). Отдых (`resolveRest`, rolls.mjs): всё Здоровье, +10 Маны не выше максимума (уже
больше максимума — не уменьшается), ручная поправка Удачи — 0 (Удача к базе, решение Сени), снимает
статус «Без отдыха». Боевой дух, Ранения, рану в ногу и попытки Мистицизма не трогает. Карточка
шёпотом владельцам и Ведущему.

**«Без отдыха» (реализация, §11).** Статус `hgUnrested` — ставит Ведущий вручную (HUD токена)
«на начало нового дня», снимает только отдых. Пока он есть, первичные навыки А, З, СМ, Зн =
⌊база / 2⌋ + артефакты (`halveBase`, `actor-hero.mjs`); максимум Маны уменьшается сам (считается от
Знаний). В подсказке навыка — «Без отдыха: база 5 → 2».

## 6. Магия

### 6.1. Общее

- Требуется Книга Магии, стоит 500 золотых
- Волшебник и Алхимик начинают с книгой: Волшебник — 2 заклинания 1-го уровня, Алхимик — 1
- Стартовый навык Мудрость даёт книгу + 1 заклинание 1-го уровня
- Дальность любого заклинания — **24 клетки**, если не сказано иное
- Длительность по умолчанию = **Сила Магии** (в раундах), уменьшается на 1 в начале хода
- Одновременно активно максимум **3 длящихся заклинания**. При наложении четвёртого одно надо снять

Уровень владения магией влияет на способ произнесения:
- начальный — вслух и с книгой в руках
- продвинутый — вслух, без книги
- эксперт — силой мысли

Признак владения Книгой Магии — наличие у героя предмета «книга магии»
(тип документа `spellbook`) среди вещей, независимо от того, надета ли
она (слот 10 папердолла — см. §8.2) или лежит в рюкзаке; отдельного поля
на актёре для этого нет. Клик по предмету книги (в папердолле или в
рюкзаке) открывает разворот книги поверх листа персонажа — до 12
заклинаний за разворот, отсортированных по уровню, затем школе, затем
названию; под иконкой — уровень и стоимость Маны по текущей ступени владения
школой (см. §6.3); клик — каст, правый клик — лист заклинания (все четыре
ступени): у Ведущего с правкой, у игрока, в том числе владельца героя, только
для чтения — права на предмет не меняются, лист открывается запертым. Открытый из книги,
лист отмечает ступень, действующую у этого героя (по его навыку школы; ступени — тёмные
панели с фаской, как под Скоростью/Зрением на листе героя, действующая — светлой золотой
линией вместо фаски, без заливки), и строкой «Недоступно: нужна … Мудрость», если её не хватает на
уровень заклинания; из компендиума — без того и другого. **Не реализовано**: требование держать
книгу в руках для начальной ступени владения магией (см. выше) —
школьные вкладки фильтрации тоже не реализованы, список в развороте
всегда один общий.

**Мудрость (реализация, §11).** Без Мудрости доступны заклинания 1–2 уровня, с Мудростью
базовой/продвинутой/экспертной — до 3/4/5. Каст выше разрешённого уровня запрещён всем,
Ведущему тоже: уведомление, Мана не списывается (`castSpell`, `canCastSpellLevel`).
Изучение не ограничено. Заклинание, выданное расой (флаг `raceGrantedItem` — «Полет»
Элементаля Воздуха), — исключение. Без Книги Магии кастуются только заклинания от расы (стр. 32:
«Для сотворения заклинаний необходимо прежде всего иметь Книгу заклинаний»; стр. 12, Воздух:
«Даже если у вас нет Книги Магии, вы все равно можете его использовать»): `castSpell` иначе
отказывает с уведомлением, Мана не списывается (`canCastWithoutSpellbook`, rolls.mjs). У героя
без книги, но с заклинанием от расы, клик по пустому слоту книги (слот 10) открывает разворот
только с такими заклинаниями; без них пустой слот не кликается, как раньше. Мана за такой каст —
по обычным правилам («Мана в таком случае тратится по стандартным правилам сотворения
заклинания»), вариант — по ступени школы. Запрет по Мудрости виден при попытке каста
(уведомление «Недоступно: нужна … Мудрость»). «Шляпа волшебника» (стр. 50) не автоматизирована.

### 6.2. Школы

Магия Земли, Магия Воздуха, Магия Воды, Магия Огня — плюс пятая, **Универсальные**
(стр. 61): заклинания вне стихий, например Волшебная Стрела (1 ур.) и Призыв
Элементаля (5 ур.).
Уровни заклинаний 1–5.

В таблице §3 нет отдельного вторичного навыка «Магия Универсальная» — только
Магия Воздуха/Земли/Воды/Огня. Как прокачивается владение Универсальными
заклинаниями, книгой не уточнено; решение Сени (§11): ступень — высшая из четырёх школ героя, при
равенстве школ ничего не спрашивается, в карточке «Школа: Универсальные».

### 6.3. Структура заклинания — ВАЖНО

У каждого заклинания **четыре варианта эффекта** по уровню владения школой:

| Вариант | Что содержит |
|---|---|
| Без Навыка | описание эффекта + стоимость Маны |
| Базовый Навык | своя стоимость Маны (эффект как без навыка) |
| Продвинутый Навык | усиленный эффект |
| Экспертный Навык | эффект на несколько целей (обычно «количество целей = СМ») |

**Лист должен показывать вариант, соответствующий уровню навыка героя в этой школе, и списывать соответствующую стоимость.**

Пример структуры (Замедление, 1 ур., Земля):
- Без Навыка: скорость цели −3 до минимума 3, длительность = СМ, стоимость 6
- Базовый: стоимость 5
- Продвинутый: скорость −6 до минимума 1
- Эксперт: работает на количество противников, равное СМ

### 6.4. Урон заклинаниями (реализация, этап 1)

Этап 1 — прямой урон по целям с подтверждением Ведущего: Волшебная Стрела, Молния, Ледяная
Молния, Взрыв, Цепная Молния, только у героев (существа кастуют как раньше: стр. 113 — «Заклинания
существ наносят заранее прописанный в описании способностей урон»). Этап 2 — ниже. Остальные 31
заклинание кастуется как раньше (карточка с текстом, Мана).

- **Эффект в модели.** У каждого варианта заклинания поле `effect` (`item-spell.mjs`): вид
  (`damage`, заготовки под этапы 2–3), цели (`single` / `chain`, доп. цели и их доля), кубы
  («+ СМ» или «за СМ»), стихия. Заполнено у пяти заклинаний этапа 1 по тексту книги. Заклинание
  у героя берёт эффект у себя, иначе у записи компендиума по `_stats.compendiumSource`, иначе
  по названию (`chooseSpellEffectVariants`); не нашлось записи — каст как раньше и предупреждение
  в консоль.
- **Цели.** Из выбранных целей (`game.user.targets`): без цели — отказ «Выберите цель», Мана не
  списана (§11); больше одной — отказ с уведомлением, Мана не списана (со специализацией «Цепная
  Молния» — до трёх, ниже). Дальность 24 клетки (стр. 32:
  «Дальность произнесения любого заклинания — 24 клетки, если не указано иное»; у всех 41
  иного не указано) меряется по сетке от ближайших клеток токенов (`tokenDistanceCells`,
  grid.mjs); дальше — отказ с уведомлением, Мана не списана. Нет токена кастующего или сетки —
  строка «Дистанция до цели не определена», каст не блокируется.
- **Цепная Молния.** Дополнительные цели — по очереди ближайшие к предыдущей цели, в том числе
  свои; кастующий, поверженные и недееспособные пропускаются (`pickChainTargets`); дальностью
  не ограничены. Получают половину полного урона, эксперт — 4 цели вместо 3.
- **Специализация «Цепная Молния»** (стр. 23, трактовка §11): урон +1d6 (отдельная строка в
  подробностях карточки), все дополнительные цели получают полный урон, и ещё две цели выбирает
  игрок — это цели, выбранные после первой (порядок выбора целей в Foundry сохраняется); дальность
  24 клетки проверяется у всех выбранных. Цепь (3, у эксперта 4) идёт от первой цели и выбранные
  пропускает (`chainLightningSpecialization`, specializations.mjs). Если до клика выбрано меньше
  трёх целей, после клика — выбор на поле (`pickChainTargetsOnField`, `chainTargetsToPick`): клик по
  токену — цель, подсказка «Ещё N цели»; кастующий, уже выбранная цель, пустая клетка, дальше 24
  клеток — отказ, выбор продолжается; Esc или правый клик — дальше без оставшихся, уже выбранные остаются.
- **Карточка Цепной Молнии** (`chainLayout`, spell-effects.mjs): в видимой части — «Цепь: первая цель
  → N по цепи, ½ урона» и «Урон: X, по цепи ½ — Y»; со специализацией — «Цепь: первая цель → N на
  выбор → M по цепи», «Урон: X — всем целям» и «Специализация: +1d6, полный урон всем, 2 цели на
  выбор». У каждой цели пометка: «первая», «на выбор», «цепь, ½» или «цепь, полный урон по
  специализации».
- **Урон.** Один бросок на каст (`spellDamageDice`): «NdS + СМ» или «X за СМ» (X бросается СМ
  раз: Взрыв при СМ 3 = 6d6 + 9); Волшебство — навык 2/3/4d6 и специализация 1d6 за уровень
  заклинания, складываются (`sorceryDice`). В подробностях карточки разбивка по строкам.
- **По каждой цели** (`resolveSpellResolution`, одна функция для карточки и для применения):
  недееспособная — погибает; иммунитет по тегам существа (`creatureSpellProfile`,
  `spellImmunity`: «Невосприимчивость к магии», «Иммунитет к заклинаниям» — ко всем; к огню, ко
  льду, к молнии — по стихии заклинания; к Армагеддону, к Метеоритному дождю — по названию) —
  урон 0; Сопротивление Магии существа, Помехи и Гном у героя — куб бросается при касте, успех —
  урон 0 (`heroSpellResistanceThreshold`: Помехи 6 / 5+ / 4+, Гном 6, Гном с Помехами на одну
  ступень лучше); иначе — полный урон × доля, затем надетый доспех 4–5 уровня — вдвое, как у атак
  (§5.5). Округление вниз. Падение и потеря сознания на магию не действуют.
- **Подтверждение.** Урон уходит в цели только после «Подтвердить» Ведущего на карточке (кнопка
  только у Ведущего, флаг `confirmed` против повторного применения); цель по uuid токена.
  Здоровье до 0 — статус «недееспособен» тем же путём, что при атаке. Мана списывается сразу, как
  раньше. Кому видна карточка — как у атаки (§10).

«Звуки заклинаний» (вкл/выкл). Звук есть у всех 41 заклинания.

**Этап 2 — усиления и ослабления с длительностью (реализация, шаги 1–4).** Благословение,
Проклятие, Слабость, Щит, Воздушный Щит — только у героев, решения по спорным местам — §11.

- **Эффект в модели.** Вид `modifier` (`item-spell.mjs`): что меняет (`damageDealt` — урон, который
  наносит носитель; `meleeDamageTaken` / `rangedDamageTaken` — физический урон, который он получает
  вблизи / издали), на сколько (со знаком), «до минимума 1», враждебное ли (сопротивление),
  «не на нежить»; у эксперта — «целей = СМ». Значения по ступеням — по тексту книги
  (стр. 53, 56, 57, 59), тест `test/spell-effects.test.mjs`.
- **Бой кастующего.** `actorCombat` (combat.mjs): начатый бой, где актёр — участник, среди всех
  боёв мира, а не `game.combat` (бой, открытый в трекере; в мире их может быть несколько). Если
  актёр в нескольких начатых боях: открытый в трекере, иначе отмеченный активным, иначе самый
  новый (`chooseActorCombat`, тест `test/combat-choice.test.mjs`).
- **Каст.** Отказ до списания Маны: вне боя — «Вне боя заклинание не действует. Ведущий может
  начать бой — тогда кастуйте»; целей больше, чем берёт вариант (1, у эксперта СМ); цель дальше 24
  клеток; нежить (тег существа «Нежить», `isUndeadCreature`) у Благословения и Проклятия; без цели —
  «Выберите цель». Иммунитет «ко всем заклинаниям» — и к полезным;
  сопротивление (Сопротивление магии, Помехи, Гном) бросается при касте только у Слабости и
  Проклятия (`resolveModifierSpellResolution`). Недееспособной цели эффект просто накладывается.
- **Подтверждение Ведущего.** Эффект (ActiveEffect с картинкой заклинания, флаг
  `flags.heroes-glory.spellEffect`) появляется на цели после «Подтвердить»: иконка на токене,
  длительность СМ раундов, истечение в начале хода. Точка отсчёта (бой, кастующий, раунд, ход)
  записывается **при касте** и передаётся эффекту явно, поэтому эффект тикает по ходам кастующего,
  даже если Ведущий подтвердил в чужой ход (проверено на стенде: наложено в раунде 1 при СМ 3 —
  держится раунды 1–3, снимается в начале хода кастующего в раунде 4). Тот же эффект на цели
  заменяется: иконка одна, длительность новая. Если бой каста уже закончен — не накладывается,
  уведомление, карточка остаётся.
- **Иконка.** У эффекта заклинания иконка показывается всегда (`showIcon` — «всегда»): ядро без
  этого показывает её на токене и в трекере только у эффекта с длительностью, а у Молитвы («до
  конца боя») длительности нет.
- **Снятие.** Истёкший эффект удаляет хук `expireSpellEffect`, по окончании боя все эффекты
  заклинаний этого боя снимает `clearSpellEffectsAfterCombat` (актёры мира и токены сцены боя,
  несвязанные тоже).
- **Атака.** При броске в карточку записываются эффекты атакующего (урон) и Щит или Воздушный Щит
  цели — по дальности этой атаки (`spellModifierEffects`). `resolveAttackResolution`: ± урона — к
  урону оружия или существа до множителя попадания (`resolveSpellDamageDealt`, разные заклинания
  складываются, «не меньше 1»); Щиты — после множителей и доспеха (`resolveSpellDamageTaken`, не
  меньше 1, промах 0). В подробностях карточки — строки «Благословение +4», «Щит −6» и «Урон до
  множителя: 3 → 7».
- **Предел 3 длящихся (стр. 32).** Перед списанием Маны считаются активные наложения этого героя
  (эффекты с его `casterUuid` на актёрах мира и несвязанных токенах всех сцен; одно наложение — одно
  заклинание, сколько бы у него ни было целей, `castId` во флаге эффекта). Наложение, которое новое
  целиком заменит (то же заклинание на тех же целях), не считается (`resolveLastingSpellLimit`,
  spell-effects.mjs). Если их уже три — окно в стиле системы (`HeroesGloryDialog`, строка на
  наложение: заклинание, цели, осталось раундов; переключатели — та же галочка HOMM3): выбранное
  заканчивается при подтверждении нового Ведущим (строка в карточке «Закончится: …» /
  «Закончено: …»); Отмена или Esc — каст отменён, Мана не списана. Неподтверждённые карточки
  длящихся заклинаний этого героя (пока жив их бой) тоже считаются — в окне строкой «… — ждёт
  подтверждения» (`isLastingSpellCard`, spell-effects.mjs); если выбрана такая, её карточка
  помечается «Отменено…» и больше не подтверждается, а Мана за неё возвращается — строка «Мана
  возвращена: N», как при отмене Ведущим (`cancelledCardRefund`). Уже применённое наложение,
  законченное так же, Ману не возвращает. Если выбранную неподтверждённую карточку Ведущий подтвердит
  раньше новой, при подтверждении новой она заканчивается уже как применённое наложение (Мана не
  возвращается) — больше трёх не бывает. При подтверждении Ведущим проверка
  повторяется по уже применённым наложениям (`confirmWithinLimit`): если с новым их стало бы
  больше трёх — то же окно у Ведущего, Отмена — ничего не применено, карточка остаётся.
- **Артефакты, удлиняющие заклинания** (стр. 49–50, ход = раунд): надетые «Магический ошейник» +1 и
  «Магическая накидка» +3 к СМ раундов (`lastingSpellRounds`, по названию предмета).
- **Кому видна карточка каста** — всех: обычной, урона, усиления — как у атаки (§10).

**Группа А1 — характеристики на время (реализация).** Каменная Кожа, Жажда Крови, Разрушительный
Луч, Точность, Ускорение, Замедление, Молитва, Удача, Неудача, Полет — тем же механизмом этапа 2
(каст, отказы до списания Маны, подтверждение Ведущего, длительность, предел 3, снятие в конце
боя). Решения — §11.

- **Модель.** У варианта список `modifiers` (у Молитвы их четыре) вместо одного `modifier`
  (`migrateData` переводит старые копии): характеристика, значение со знаком, «до минимума N»
  (`floor`). Новые характеристики: Атака, Защита, Скорость, Удача, «Атака в дальнем бою»
  (`rangedAttack`). Ещё поля: «до конца боя» (Молитва), статус (Полет — `fly` ядра, только
  иконка), «вне боя — карточка с текстом» (Полет). Значения по ступеням — по тексту книги
  (стр. 53, 55, 56, 58, 59, 60), тест `test/spell-effects.test.mjs`.
- **Где применяется.** Эффект — ActiveEffect с флагом `spellEffect`, без `system.changes`.
  Атаку, Защиту и Скорость считает `prepareDerivedData` героя (после «Без отдыха», артефактов,
  раны в ногу, Поиска пути) и существа (поверх статблока): `applySpellStatModifiers`
  (spell-effects.mjs) — разные заклинания складываются; «до минимума N»: итог = max(значение + Σ,
  min(значение, N)), то есть не ниже N, но и не поднимает значение, которое уже ниже; при
  нескольких полах — наибольший. Удача — у героя отдельной частью суммы до ограничения ±3, которое
  и даёт «до максимума в 3» / «до минимума в -3». «Атака в дальнем бою» (Точность) прибавляется к
  Атаке в карточке атаки, только при дальней атаке. Урон Молитвы — как у Благословения, до
  множителя. В подробностях карточки атаки — строки «Жажда Крови: Атака +3», «Разрушительный Луч:
  Защита −5 (не ниже 0)»; в подсказках Атаки, Защиты, Скорости и Удачи на листе героя — часть
  «Заклинания: ±N».
- **Каст.** Как в этапе 2, плюс: Удача и Неудача на существо — отказ «у существа нет Удачи»;
  Полет вне боя — карточка с текстом и списание Маны, без эффекта; у Молитвы вместо раундов «до
  конца боя» (в карточке и в окне предела 3), эффект без длительности, снимается в конце боя.
  Враждебные (Замедление, Разрушительный Луч, Неудача) — сопротивление, как у Слабости.
  Специализация «Ускорение» (стр. 23) — +3 к Скорости заклинания, запоминается при касте
  (`hasteSpecializationBonus`). Других специализаций на заклинания А1 в книге нет.
- **Трата Удачи.** Переброс за Удачу сначала тратит Удачу или Неудачу заклинания (на 0 эффект
  снимается), потом ручную поправку; итог сдвигается на 1 к нулю, как раньше
  (`spendLuckWithSpells`, rolls.mjs).

**Шаг 4 — «в поле зрения»: Волна Смерти, Уничтожить Нежить, Армагеддон (реализация).** Урон этапа 1
(один бросок на каст с Волшебством, иммунитеты, сопротивление, доспех 4–5 вдвое, недееспособный
гибнет, подтверждение Ведущего), но цели собирает само заклинание; выбранные цели (T) не нужны и не
учитываются. Решения — §11.

- **Кто попадает** (`visibleSpellTargets`, roll-actions.mjs): токены с актёром на сцене кастующего,
  на его уровне, в пределах сцены, не скрытые, не «повержен» (недееспособные — да); отбор по
  заклинанию — `visibleSpellTakes`: Волна Смерти — все, кроме существ с тегом «Нежить» или
  «Элементаль»; Уничтожить Нежить — только существа с тегом «Нежить»; Армагеддон — все, в том числе
  кастующий. Союзники — да; кастующий — только у Армагеддона.
- **Видимость** (`tokenInSight`, grid.mjs): линия от центра токена кастующего к центру любой клетки
  цели не пересекает стен зрения; открытые двери пропускают, темнота не учитывается. Предела 24
  клетки нет.
- **Отказ до списания Маны:** нет токена кастующего на сцене; никого в поле зрения.
- **Карточка:** строка на каждую цель; у Ведущего до подтверждения рядом с каждой — «исключить» /
  «вернуть» (`toggleSpellTargetExcluded`); исключённая цель ничего не получает. Антимагия и
  иммунитеты — строкой у цели. Сопротивление бросается у всех, союзников и кастующего тоже. Работает
  и вне боя.

**Шаг 5 — «Выберите клетку»: Метеоритный Дождь, Огненный Шар, Инферно, Кольцо Холода
(реализация).** Урон этапа 1 (один бросок на каст с Волшебством, иммунитеты, сопротивление, доспех
4–5 вдвое, недееспособный гибнет, подтверждение Ведущего); выбранные цели (T) не нужны. Решения —
§11.

- **Выбор клетки** (`areaSpellTargets`, roll-actions.mjs): регион ядра без сохранения
  (`canvas.regions.placeRegion`, `create:false`, форма `grid`) — узор тянется за курсором по
  клеткам, левый клик — выбрать, правый клик или Esc — отмена (любой пустой результат), поворота
  нет. Центр — не дальше 24 клеток от токена кастующего (`preConfirm`, `tokenCellDistance`, grid.mjs):
  дальше — уведомление, выбор продолжается. Пустая клетка — можно; видимость не проверяется, стены
  область не режут.
- **Узор** (`areaCells`, spell-effects.mjs): клетка и соседние — 3×3 (Метеоритный Дождь, Огненный
  Шар, Инферно); Инферно продвинутый и эксперт — 5×5; Кольцо Холода — 8 соседних без центра.
  Соседи — по сетке сцены (диагональ — соседняя клетка).
- **Кто попадает:** токены с актёром на уровне кастующего, в пределах сцены, не скрытые, не
  «повержен» (недееспособные — да), у которых хоть одна клетка в узоре (`tokenInArea`) — союзники
  и сам кастующий тоже.
- **Отказ до списания Маны:** нет токена кастующего на сцене; сцена без сетки; выбор отменён; в
  области никого.
- **Карточка:** строка «Центр: клетка — столбец …, ряд …» (и кто там стоит), строка на цель, у
  Ведущего до подтверждения «исключить» / «вернуть». Антимагия и иммунитеты — строкой у цели.
  Работает и вне боя.

**Группа Г — Телепорт, Силовое Поле, Стена Огня, Зыбучий Песок (реализация).** Решения — §11. Значения по
ступеням — по книге (стр. 54, 58, 59), тест `test/spell-effects.test.mjs`.

- **Телепорт** (стр. 58, `castTeleportSpell`). Цель — одна (T), в 24 клетках, на стороне кастующего
  (та же disposition токена). Кастующий ставит на сцене отпечаток размером с токен цели (регион ядра
  без сохранения): все клетки свободны от чужих токенов, в пределах сцены, не в Силовом Поле, хотя
  бы одну видно от центра токена кастующего (`pointInSight`, grid.mjs); предела дальности для клетки
  нет. Правый клик или Esc — отмена, Мана не списана. Ведущий подтверждает — токен переносится
  движением ядра `displace` (сквозь стены; в Стену Огня и ловушку — без срабатывания входа). Работает
  и вне боя, в предел 3 не входит.
- **Силовое Поле и Стена Огня** (стр. 54, 59, `castFieldSpell`). Только в бою, длящиеся (предел 3).
  Клетки выбираются по одной (регион ядра без сохранения, форма на клетку): не дальше 24 клеток от
  кастующего, в пределах сцены, цепочкой — каждая рядом хотя бы с одной выбранной
  (`fieldCellChoice`); у Стены Огня — без существ. Правый клик или Esc на любой клетке — отмена
  всего каста. Клеток: Силовое Поле 2 / 3 / 4, Стена Огня 2 / 3 / 3, со специализацией «Стена Огня»
  (стр. 23) +1 клетка и +5d6 к урону (`fireWallSpecialization`). Ведущий подтверждает — на сцене
  появляется регион (флаг `fieldSpell`): Силовое Поле — со своим поведением `heroes-glory.forceField`,
  бесконечная стоимость движения по клеткам — ни войти, ни выйти, ходьбой и полётом; телепорт
  (`displace`) проходит. Бесконечность — `difficulty: null` местности: core `TerrainData` перемножает
  сложности и превращает `null` в 0, поэтому местность у системы своя (`HeroesGloryTerrainData`,
  `CONFIG.Token.movement.TerrainData`). Ведущий с настройкой ядра «движение без ограничений» проходит
  и сквозь поле, как сквозь стены. Ограничение `restriction` у региона в v14 — не барьер, а обрезка
  фигуры стенами. Стена Огня — со своим
  поведением `heroes-glory.fireWall`. Оба видны всем,
  держатся СМ раундов (+ артефакты-удлинители) и снимаются в начале хода кастующего
  (`expireFieldSpells`, хук `combatTurnChange`), в конце боя — все (`clearFieldSpellsAfterCombat`).
  В окне предела 3 — строкой «… — на сцене».
- **Стена Огня жжёт** (`burnFireWall`): при входе токена и в начале его хода в стене активный Ведущий
  бросает урон, замороженный при касте — (1d6 / +1 / +2) за каждый СМ кастующего, плюс Волшебство и
  специализация — и выкладывает карточку урона на подтверждение: иммунитет к огню, сопротивление при
  каждом срабатывании, доспех 4–5 вдвое, недееспособный гибнет. Строка «вошёл в Стену Огня» / «начал
  ход в Стене Огня»; специализация — отдельной строкой «Специализация «Стена Огня»: +5d6».
- **Зыбучий Песок** (стр. 53, тот же `castFieldSpell`). Только в бою, до конца боя, в предел 3 не
  входит. Ловушек 4 / 4 / 6 / 8, клетки по одной: не дальше 24 клеток, в пределах сцены, без существ,
  рядом быть не обязаны; правый клик или Esc — отмена всего каста. Карточка — шёпотом владельцам
  кастующего и Ведущему (в ней клетки). Ведущий подтверждает — каждая ловушка отдельным регионом с
  поведением `heroes-glory.quicksand`: видимость OBSERVER, права на регион — Наблюдатель у
  владельцев кастующего (`quicksandOwnership`), так что видят их только они и Ведущий. Вход в
  ловушку любого токена, кастующего тоже (не `displace`): клиент двигавшего останавливает движение
  (`stopMovement`, как поведение ядра «пауза»), активный Ведущий открывает ловушку всем — она
  остаётся до конца боя и срабатывает снова — и пишет в чат ««X» попал в Зыбучий Песок — ход
  окончен» (`springQuicksand`); ход передаёт Ведущий. Ядро останавливает токен там, где он пересёк
  границу региона, не по сетке, — Ведущий после анимации ставит его в клетку ловушки движением
  `displace` (без повторного срабатывания). В конце боя снимаются все.
- **Развеивание Магии, эксперт: видимый эффект** (стр. 57, `castDispelCellSpell`). Без выбранных
  целей (T) — выбор клетки (регион ядра без сохранения) не дальше 24 клеток; на клетке должен быть
  хоть один наш регион (Силовое Поле, Стена Огня, ловушка), который этот пользователь видит
  (`dispelCellRegionIds`), иначе выбор продолжается. Правый клик или Esc — отмена, Мана не списана.
  Карточка «Клетка — столбец …, ряд …: снимет …»; Ведущий подтверждает — эти регионы удаляются целиком.
  Невидимая для кастующего ловушка остаётся. Работает и вне боя. С выбранными целями — как раньше.
  Копии заклинания у героев, сделанные раньше, получают признак при загрузке (`migrateData`,
  item-spell.mjs: экспертный `dispel` без поля `dispelFields`).
- **Перенос `displace` и регионы.** Ядро строит дерево полигонов региона лениво (геттер
  `polygonTree`, его вызывает отрисовка), а проверка `displace` читает приватное поле напрямую:
  регион, ещё не нарисованный на этом клиенте (свежая ловушка, невидимая ловушка), роняет перенос
  с ошибкой «reading 'testPoint'». Наши переносы (Телепорт, ловушка) идут через `displaceToken`,
  который сначала обращается к геттеру.

**Группа Д — Призыв Элементаля, Клон (реализация).** Решения — §11. Значения по ступеням — по книге
(стр. 58, 61), тест `test/spell-effects.test.mjs`.

- **Стихия.** До каста — окно системы: Огонь, Воздух, Земля, Вода, у каждой строки вариант и Мана
  по навыку магии этой стихии (`elementSpellVariant`), не по высшей из
  четырёх, как у прочих Универсальных; на листе героя выбор школы для Призыва не показывается
  (`spellChoosesElement`). Элементаль — базовый этой стихии из бестиария (`SUMMON_ELEMENTALS`:
  Огненные, Воздушные, Элементали Земли, Элементали Воды).
- **Каст** (`castSummonSpell`). Только в бою, длящееся (предел 3). Пока жив прежний элементаль
  кастующего — отказ до списания Маны («одного Элементаля за раз»). Кастующий ставит отпечаток
  размером с токен существа: свободные клетки, в пределах сцены, не в Силовом Поле, не дальше 24
  клеток; видимость не проверяется. Правый клик или Esc — отмена, Мана не списана. Размер токена
  берётся из компендиума (Элементали Воды — «Большое существо», 2×2, §9).
- **Подтверждение Ведущего** (`confirmSummonSpell`). Актёр стихии один раз импортируется в папку
  «Heroes & Glory — призванные» (флаг `summonBase`, прав у игроков нет) и дальше переиспользуется;
  токен несвязанный, в его дельте — статблок с бонусами (+2 / +4 к Атаке и Урону, +10 / +20 к
  Здоровью, полное; `summonedCreatureStats`) и права Владельца у не-Ведущих владельцев героя
  (`summonOwnership`). Сторона — disposition токена кастующего. Флаг токена `summoned`.
  Имя токена и участника — «X (призван)», у клона — «Клон: X», чтобы в трекере их отличать.
  Отпечаток размером с токен (Телепорт большого, Призыв, Клон) держится курсором за середину, а не
  за левую верхнюю клетку (`footprintAnchor`).
  Участник боя с инициативой кастующего и флагом `follows` — ходит сразу после кастующего,
  с этого же раунда (`HeroesGloryCombat#setupTurns`, `orderWithFollowers`); текущий ход при
  добавлении не сдвигается (опция ядра `combatTurn`).
- **Исчезает** (`dismissSummoned`, helpers/combat.mjs): в начале хода кастующего в раунде «каст +
  СМ» (`expireSummons`), при Здоровье 0 — сразу, без статусов, строкой «погиб и исчезает»
  (documents/actor.mjs), в конце боя, при окончании наложения по пределу 3. В окно опыта не
  попадает. Лист существа владелец такого токена открывает (исключение из «только Ведущему»); режим
  правки на листе — по-прежнему только у Ведущего.
- **Клон** (стр. 58, `castCloneSpell`). Только в бою, длящееся (предел 3). Цель — одна (T): существо,
  на стороне кастующего (та же disposition токена), не дальше 24 клеток, не клон (клон призванного —
  можно); Антимагия — отказ. Статблок и текущее Здоровье копируются при касте (исходные данные
  актёра, без эффектов заклинаний и статусов). Со специализацией «Клон» (стр. 23) — окно «один / два
  за двойную Ману» (`cloneSpecialization`), оба — одно наложение. Отпечатки ставятся по одному:
  свободные клетки размером с токен оригинала, в пределах сцены, не в Силовом Поле, не дальше 24
  клеток; правый клик или Esc — отмена всего каста. Ведущий подтверждает (`confirmCloneSpell`) —
  несвязанный токен на актёре оригинала: имя и картинка оригинала, в дельте — снимок статблока,
  права Владельца у игроков кастующего, собственные эффекты актёра погашены; сторона кастующего;
  ходит сразу после кастующего. Исчезает при любом уменьшении Здоровья (промах и урон 0 — нет;
  documents/actor.mjs, строка «получил урон и исчезает»), по истечении СМ раундов, в конце боя;
  в окно опыта не попадает.

**Группа А2 — Антимагия, Забывчивость, Огненный Щит, Слепота (реализация).** Механизм этапа 2:
каст, отказы до списания Маны, подтверждение Ведущего, только в бою. Значения по ступеням — по книге
(стр. 54, 56, 58, 59, 60), тест `test/spell-effects.test.mjs`. Решения — §11.

- **Антимагия** (стр. 54). Иммунитет к заклинаниям 1–3 / 1–4 / 1–5 уровня, СМ раундов: все заклинания
  этих уровней, свои и чужие, полезные и вредные, кроме Развеивания Магии и повтора самой Антимагии
  (`antimagicBlocks`). Одна выбранная цель под Антимагией — отказ до списания Маны; при нескольких —
  строка «иммунитет (Антимагия)». Снимается Развеиванием. Так же отказывает до списания Маны
  иммунитет единственной выбранной цели по тегам существа — к стихии, к магии разума, ко всем
  заклинаниям, к этому заклинанию (`soleTargetRefuses`); при нескольких целях (и у Цепной Молнии) —
  строка у цели, как раньше.
- **Забывчивость** (стр. 58). Дальняя серия на 1 меньше; продвинутый и эксперт — стрелять нельзя
  (`rangedSeriesAfterSpells`). Серия 0 — дальняя атака отказывает с уведомлением. Ближние не
  затрагиваются. Враждебная; эксперт — на СМ целей. Если у цели не остаётся выстрелов (например, у
  существа с одной атакой), её строка в карточке — «стрелять не может», не «меньше на 1»
  (`rangedSeriesOf` при касте).
- **Огненный Щит** (стр. 60). СМ кастующего на момент каста (+3 / +6). Любая атака по носителю —
  оружием или естественная, ближняя или дальняя, при промахе тоже, каждая атака серии — строка в
  карточке «Огненный Щит: «X» получит N огнём»; урон уходит атакующему той же кнопкой «Подтвердить».
  Иммунитет к огню — 0, надетый доспех 4–5 уровня — вдвое, без множителей и сопротивления
  (`resolveFireShieldDamage`). При добивании недееспособного — строка под добиванием, урон сразу.
  Атакующий, выбывший от щита, — «Следующая атака» скрывается («атакующий выбыл из боя»).
- **Слепота** (стр. 59). Сопротивление, затем d6 4+ / 3+ / 2+ при касте; одна цель. Эффект разума:
  иммунны Нежить, Голем, Элементаль, теги «Иммунитет к Магии Разума» и «Иммунитет к Ослеплению» (расы
  героев — нет). Сработала — статус «Ослеплён»; в начале хода цели строка ««X» пропускает ход
  (Слепота)», ход передаёт Ведущий; в конце этого хода эффект снимается (`advanceBlindness`, хук
  `combatTurnChange`). Снимают урон (любое уменьшение Здоровья), Лечение, Развеивание. В предел 3
  длящихся не входит.
- **Ответный Удар** (стр. 56) и тег существа «Ответная атака» (стр. 115). На подтверждённой карточке
  ближней атаки — кнопка «Ответный удар (осталось N)» владельцам цели и Ведущему: одна атака цели по
  атакующему, своя карточка с подтверждением, Огненный Щит и прочее работают как обычно. Только в
  бою, только на ближние атаки, ответ на ответ не вызывает ответа, обе стороны должны быть в строю,
  на одну карточку — один ответ. В раунд: заклинание — 1, продвинутое — 2, эксперт — на СМ целей;
  тег «Ответная Атака (N)» — N, «(Неограничено)» — без счётчика; тег и заклинание не складываются,
  берётся большее (`counterAttackOffer`, rolls.mjs). Счётчик — флаг актёра на бой и раунд. Герой
  отвечает надетым оружием ближнего боя, без него кнопки нет.

**Группа В — Лечение, Развеивание Магии, Воскрешение (реализация).** Мгновенные, у героев: каст
с отказами до списания Маны, подтверждение Ведущего, карточка как у остальных (§10). В предел 3
длящихся не входят. Вид эффекта — `heal`, `dispel`, `resurrect` (`item-spell.mjs`), значения по
ступеням — по книге (стр. 54, 57), тест `test/spell-effects.test.mjs`; что применяется —
`resolveSupportSpellResolution` (spell-effects.mjs), одна функция для карточки и подтверждения.
Решения — §11.

- **Лечение** (стр. 57). Один бросок 1d6/2d6/3d6 + СМ на все цели, не выше максимума Здоровья;
  эксперт — до СМ целей. Снимает негативные заклинания с любого кастующего (`NEGATIVE_SPELLS`:
  Разрушительный Луч, Замедление, Слабость, Проклятие, Неудача, Забывчивость, Слепота) и статусы
  ядра, поставленные Ведущим за способности существ (стр. 113–115): Паралич, Болезнь,
  «Проклятие». Цель недееспособная или погибшая — отказ «поможет только Воскрешение». Работает и
  вне боя.
- **Развеивание Магии** (стр. 57). Снимает все эффекты заклинаний (с ними — статус «Полёт») и
  статусы Ослепление, Паралич, «Проклятие». Без навыка и базовый — только цель на стороне
  кастующего: та же disposition токена, без токена кастующего — дружественная
  (`isFriendlyTarget`), иначе отказ; продвинутый — любая; эксперт — до СМ целей. По цели не на
  стороне кастующего заклинание враждебное: бросается сопротивление (Сопротивление магии, Помехи,
  Гном). «Защиту», «Не обнаружил врага», «Без отдыха», падение, рану в ногу не трогает. Экспертное
  «убрать видимый эффект» — по клетке, группа Г ниже. Работает и вне боя.
- **Воскрешение** (стр. 54). Только в бою; цель — участник боя кастующего с «недееспособен» или
  «повержен»; Нежить, Голем, Элементаль (стр. 114, 116) — отказ. Снимает «повержен»,
  «недееспособен», «без сознания» («упал» остаётся), Здоровье ⌊50% максимума⌋, у эксперта —
  полное; участник остаётся в бою со своей инициативой. Без навыка и базовый — «до конца боя»:
  в конце боя (`endTemporaryResurrections`, helpers/combat.mjs) погибший снова «повержен»,
  недееспособный снова «недееспособен» (Здоровье 0), дальше обычная проверка после боя; Ранения
  при подтверждении нет. Продвинутый и эксперт — навсегда, герой получает +1 Ранение (стр. 32),
  со специализацией «Воскрешение» — без него (стр. 23, `resurrectionSpecialization`). Если бой
  закончился до подтверждения, временное Воскрешение не применяется.

## 7. Небоевые проверки

Бросок **d20 + бонусы** против сложности:

| Сложность | Значение |
|---|---|
| Лёгкая | 5 |
| Средняя | 10 |
| Сложная | 15 |
| Очень сложная | 20 |
| Невозможная | 25+ |

Какая характеристика проверяется:

| Характеристика | Область |
|---|---|
| Атака | физическая сила, взаимодействие со средой |
| Защита | избежать опасного воздействия |
| Сила Магии | магия, ритуалы, руны |
| Знания | умственная активность, поиск улик, переговоры |

Рассказчик может дать +2…+5 за расу, класс или навык.
Социальные броски — модификатор отношений фракций (таблица «Тест на дружелюбность», стр. 65).

## 8. Снаряжение

### 8.1. Оружие

Поля: **название, тип, урон, где встречается, эпик-таблица (6 строк)**.

Типы: Колющий, Рубящий, Дробящий, Колющий/рубящий, Стрелковое. Флаг **Двуручное**.

Урон от 2 до 60. Стартовый урон: оружие Воина 5, оружие Волшебника 3, стрелковое 5 (ближний бой при этом 3). **Без оружия урон = 1**, если не сказано иного.

Эпик-таблица привязана к **категории** оружия (древковое, клинковое, топоры, дробящее, стрелковое), а не к конкретному предмету.

Ограничение: одновременно только одно оружие ближнего боя и одно дальнего.

**Картинки оружия (реализация).** У 40 из 41 обычного оружия — тайл 32×32 из Dungeon Crawl Stone Soup,
у Пистоля — из CC0 Firearm Icons (огнестрельного в DCSS нет); всё CC0, `assets/weapons/`, источники
в `README.md` там же; выбор Сени по витрине (`WEAPON_ICONS`, `scripts/data/weapon-compendium-data.mjs`).
Стартовое оружие при создании героя — тоже DCSS: волшебнику кинжал, воину меч; для стрелка готовы лук
и нож, но стрелковое оружие при создании пока не выдаётся (§2.7, §11). На листах картинка растягивается
на ячейку, как артефакт, без сглаживания.

### 8.2. Артефакты — 6 типов

1. Зачарованное оружие
2. Зачарованные доспехи
3. Зачарованные щиты
4. Ожерелья
5. Волшебная одежда
6. Волшебные предметы

Случайный артефакт: бросок d6 по типу, затем по таблице.
Бонусы — текстом («+4 к Атаке», «+3 ко всем характеристикам», «Восстанавливает 1 ОЗ за каждый факт нанесения урона»).

В модели данных числовые бонусы на одну характеристику («+4 к Атаке») дополнительно
хранятся структурированно (`modifiers` у artifact: список {характеристика, режим, значение})
и применяются через Active Effects, только пока предмет надет. В книге все такие бонусы —
«+N» или «−N», поэтому в компендиуме у всех режим «прибавить», минус — отрицательным
значением («Гладиус титана»: Атака +2, Защита −3). На листе режима нет: строка
«характеристика — число со знаком». «Ко всем характеристикам» — четыре первичных (§11).
Бонусы, не сводящиеся к числу на владельце («Восстанавливает 1 ОЗ за каждый факт нанесения
урона», «в течение дня», против противника, навыки) остаются только текстом в `bonus`,
без автоматизации.

**Лист артефакта (реализация).** В стиле героя, на общем классе окна предмета. Поля оружия
(тип, урон, двуручное) — только у зачарованного оружия, «Уровень» — только у доспехов и
щитов, «Экипировано» нет (надевает кукла). «Куда надевается» — мини-кукла: те же 19 ячеек,
что на листе героя, клик отмечает или снимает одну ячейку (у любого артефакта, включая
оружие; кольца, «прочее» и резерв 17–19 — по отдельности); заперт только слот книги (10, §11).
Менять может владелец предмета, у игрока без прав — только чтение. Кукла героя принимает
артефакт ровно в отмеченные слоты (`paperdollSlotAccepts`). У зачарованного оружия в компендиуме
отмечен слот его типа (ближнее — 1, стрелковое — 16); без отметок действует этот же слот; при
смене типа отметка переезжает, если её не меняли руками (`followWeaponTypeSlots`). Правило «одно
ближнее + одно дальнее» и вид атаки (ближняя/дальняя) зависят от типа оружия, не от слота: меч,
надетый в слот 6, атакует из него как ближний.

**Картинки артефактов (реализация).** У каждого из 71 — кадр HOMM3 `Artifact.def`
(`assets/artifact/`, кадр N = артефакт N в `ARTRAITS.TXT`), сопоставление утверждено Сеней по листу
сверки (`ARTIFACT_FRAMES`, `scripts/data/artifact-compendium-data.mjs`): по названию, по тому же
эффекту в HOMM3 или по смыслу; повторы кадров — только у щитов (в HOMM3 их 8, у нас 15). Книга
Магии — кадр 0 «Книга заклинаний», у любой новой книги (`getDefaultArtwork`, documents/item.mjs).

Зачарованные доспехи дополнительно несут **Уровень (1–5)** — как обычные доспехи §5.5
(в таблице артефактов запись вида «доспех (1 уровень)»): доспех по уровню гасит последствия
эпик-попадания. Зачарованные щиты уровня **не несут в книге** — в таблице артефактов
(стр. 48) колонка «Тип» для всех них просто «щит», без номера уровня, в отличие от
доспехов; предыдущая версия этого раздела ошибочно утверждала обратное. В модели данных
у щита `level` теперь всё же есть (то же поле, что у доспеха), но по умолчанию `null` для
всех 10 книжных записей — книга не даёт значения ни одной из них, Ведущий проставляет
вручную на конкретном выданном предмете. Из уровня синтезируется `+level` к Защите
(`module/documents/item.mjs`, `#effectiveModifiers`) — прямое чтение фразы «+1–5 в
зависимости от уровня щита», отдельно от табличного бонуса конкретного предмета (тот
складывается сверх, не вместо — «дополнительный бонус сверх описанного выше»). У
остальных 4 типов артефактов уровня по-прежнему нет.

И доспехи, и щиты книга не даёт как отдельную покупаемую/стартовую позицию — только
через артефактные таблицы. Для доспеха, который герой может получить без магического
бонуса (нужно для §5.5's эпик-митигации независимо от артефактов), в компендиум добавлены
5 записей «Доспех (N уровень)» и 5 «Щит (N уровень)», без bonus/modifiers, тот же
`artifactType` — см. §11.

`targetSlots` (см. §8.2 выше, назначение слотов) для 11 записей «Зачарованные доспехи»
куратор по названию: «Шлем...» → slot_3 (голова), «Поножи...» → slot_9 (ноги), остальное
(нагрудник/кольчуга/туника/общий «доспех») → slot_5 (торс). Для всех 10 «Зачарованные
щиты» и 5 «Щит (N уровень)» — slot_6. Для 5 «Доспех (N уровень)» — все три доспеховых
слота сразу ([3, 5, 9]): Ведущий решает при выдаче, чем именно является конкретный
экземпляр.

**Назначение слотов папердолла (19 позиций, из макета листа персонажа):**
slot_1 — основная рука (оружие ближнего боя); slot_2 — предплечье/кольцо,
основная рука; slot_3 — голова; slot_4 — шея/ожерелье; slot_5 — торс;
slot_6 — вторая (левая) рука/щит; slot_7 — предплечье/кольцо, левая рука;
slot_8 — плащ/спина; slot_9 — ноги; slot_10 — книга магии; slot_11–15 —
предметы, которые носятся с собой, но не подходят ни под одно из
перечисленных мест; slot_16 — оружие дальнего боя; slot_17–19 — запасные,
назначение не определено. Соответствие проверяется: `paperdollSlotAccepts`
(`module/helpers/paperdoll-slots.mjs`) сверяет `system.targetSlots`
предмета со слотом при перетаскивании — оружие и книга магии детерминированы
по типу, артефакты (включая зачарованное оружие) — по своим отметкам, заданным в компендиуме
(правило — §11, «Куда надевается артефакт»); Ведущий правит их на листе артефакта.

### 8.3. Инвентарь

- **5 предметов** (по договорённости с Рассказчиком может меняться)
- не более **4 магических предметов** в сумке
- надетое сверх лимита бонусов не даёт

В реализации ограничения «инвентарь — 5 предметов» и «не более 4
магических предметов в сумке» **не проверяются**: рюкзак на листе
персонажа вмещает произвольное число предметов, показывая по 5 за раз
через стрелки листания. Сознательное решение при переходе на
перетаскиваемый папердолл — не отдельная задача.

Дополнительно:

- **Эпик-таблица** — 6 строк художественного описания

Частые особые навыки: Летает, Стрелок, Нежить, Большой, Ответная Атака, иммунитеты.

**Дикая мораль (реализация, §11).** Число из тега статблока («Дикая Мораль 6» / «5+») —
порог теста на повтор хода вместо 4+, поле `moraleThreshold` модели существа. Заполняется при
сборке компендиума из тегов (`wildMoraleThreshold`, creature-abilities.mjs) — сейчас только у
Минотавров (6) и Королей Минотавров (5), стр. 95. На карточке теста — «Дикая мораль: нужно N+».

**Компендиум «Бестиарий» (реализация; перенесены все 10 фракций — 141 существо).** Статблоки не перепечатываются
руками и не берутся обычным текстом PDF (он уже путал подписи статблоков рас): их извлекает
`scripts/extract_bestiary.py` по геометрии страницы — статблок по ячейкам размеченной таблицы,
строку ×0.5/×1/×2 по таблице или по координатам, эпик-таблицу из серой плашки с привязкой
каждой строки к ближайшему номеру по вертикальному центру (двухстрочные пункты книга
центрирует между строками). Результат — `scripts/data/bestiary/<фракция>.json`, сверенный с
картинками страниц; `scripts/data/creature-compendium-data.mjs` только раскладывает его по
модели существа. Всё, что решает человек (порядок статей, кадры портретов, словесное описание
пиктограмм, исправления опечаток, флаг «легендарное»), лежит в `FACTIONS` скрипта — повторный
запуск даёт тот же JSON. Инварианты данных проверяются тестом `test/creature-data.test.mjs`.

- Пара существ (базовое + улучшенное) делит эпик-таблицу и художественный текст статьи;
  диапазоны книги («1-2») раскладываются в 6 строк дублированием.
- Особые навыки — теги, разделённые запятыми/точками верхнего уровня; всё внутри скобок
  (заклинания, заряды) остаётся одним тегом.
- «Большое существо» (стр. 113: «занимает 4 соседние клетки») — прототип токена 2×2 у всех 42
  существ с этим тегом (`isLargeCreature`, creature-abilities.mjs; сборка — `size` в
  `buildActorDocument`, scripts/lib/pack-builder.mjs); остальные 1×1. Написание тега в книге
  разное — приведено к одному (§11, дефекты). Уже поставленные в мире токены и импортированные
  актёры размер не меняют.
- `system.description` (HTML): сначала то, что модель не держит — пиктограмма «Куда попал»
  (буквальное описание нарисованного + вырез из книги, `assets/bestiary/`) и магия с зарядами,
  затем художественный текст статьи. Только текст книги, без наших пометок.
- Портреты — кадры HOMM3 `TwCrPort.def` (`assets/twcrport/`), кадр = id существа в HOMM3 + 2,
  сверены по картинкам. Причала в SoD нет — его портреты из HotA-копии того же набора
  (HotA_1.8, формат `D32F`, 202 кадра) в отдельной папке `assets/twcrport-hota/`: кадры
  0–150 у HotA частично перерисованы, это не SoD-портреты. `scripts/def2png.py` читает
  `D32F` по разметке из `homm3data` (github.com/Laserlicht/homm3data, MIT); вывод для
  старых форматов не изменился (проверено попиксельно на 50 DEF, 1441 кадр).
- Слова, набранные вперемешку латиницей и кириллицей (у Корсаров «Cтрелок» с латинской «C»),
  глазами не видны — их ловит автоматическая проверка первого слоя.
- Компендиум виден только Ведущему (у игроков нет доступа) — статблоки противников.

**Компендиум «База знаний» (`knowledge-base`, реализация).** Справочные журналы системы — записями
одного журнального компендиума, а не компендиумом на каждый: «Способности существ» и «Справочник
цен». Новый справочник — новая запись там же. Виден игрокам (только чтение); права в компендиуме
общие на весь компендиум, так что справочник только для Ведущего пошёл бы отдельным компендиумом.
Номера записей и страниц считаются из названий, поэтому при переезде из прежних двух компендиумов
не изменились — поменялась только часть адреса с именем компендиума. Сохранённые ссылки на наши
компендиумы в паках и в мире проверяет `npm run check:links [-- <папка мира>]` (Foundry закрыт).

**Журнал «Способности существ» (запись «Базы знаний», реализация).** 55 способностей
со стр. 113–116 — один JournalEntry, одна страница на способность, страницы по алфавиту: список
страниц и поиск журнала фильтруют по имени, так что тег с листа существа находится вводом
названия. Текст извлекает `scripts/extract_creature_abilities.py` (начало способности — жирный
курсив «Название:»), сверено глазами по вырезам; дословно, опечатки по общему правилу.

**Теги ведут в журнал (реализация).** Тег на листе существа сам — ссылка на его страницу журнала
(у тега с двумя статьями — на первую); работает одинаково у существа из компендиума и у созданного вручную. Тег
сопоставляется с названием страницы без чисел, порогов и скобок («Регенерация 2d6» →
«Регенерация», «Яд 4+ (3d6 урона ядом)» → «Яд»), без учёта регистра и «ё». Где книга пишет
тег иначе, чем названа способность, — таблица соответствий (`ABILITY_TAG_ALIASES`,
`module/helpers/creature-abilities.mjs`): «Летает» → «Полёт», «Большой» → «Большое существо»,
«Атакует Магией» → «Атака магией», «Атакует/Атакуют всех вокруг» → «Атака всех вокруг»,
«Возрождаются» → «Возрождение», «Проклятье», «Проклятье Выстрел» → «Проклятие», «Меткий
Выстрел» → «Меткий»; «Иммунитет к Ослеплению и Окаменению» и «Иммунитет к Молниям и
Армагеддону» дают по две ссылки. Теги без статьи в книге остаются текстом: «Огненный Щит»,
«Наносит 4d6+4 / 8d6+8 урона при промахе», «Иммунитет к заклинаниям», «Ледяная Молния и
Кольцо Холода» (тест `test/creature-data.test.mjs` держит этот список).

**Лист существа (реализация).** Только для Ведущего: игрок не открывает его ни при каком уровне
доступа (даже «Владелец») — ни двойным кликом по токену, ни из списка актёров, трекера боя, ссылки
в чате или журнале; вместо окна — уведомление «Лист существа доступен только Ведущему»
(`render`, creature-sheet.mjs). Окно — в стиле героя на общей рамке листов предметов
(`framed-sheet-mixin.mjs`: масштаб, наш список, раскрытие, фокус с клавиатуры), цвет рамки — по
фракции существа. Обычный режим — раскладка окна существа HOMM3 (CrStkPu): портрет, столбец строк
с иконками окна (Атака, Защита, Урон, Атак за раунд — иконка выстрелов, Здоровье, Скорость),
числа текстом; ниже Боевой дух (иконка IMRL22) и «Дикая мораль: N+», если задана; теги-ссылки;
кнопки атаки (у «Стрелка» — «Ближняя» и «Дальняя»), «Защита», «Боевой дух» (когда тест доступен);
эпик-таблица и Описание свёрнуты. «Урон ×0.5 / ×2» на листе нет — урон считает карточка атаки.
Текущее Здоровье — поле быстрого ввода без режима правки: «12» — новое значение, «−7» / «+3» —
изменить текущее (`parseHealthInput`, rolls.mjs), Enter или уход из поля, не ниже 0. Запись тем же
обновлением актёра, что урон от атаки, поэтому 0 даёт «недееспособен» тем же путём; подъём этим
полем с 0 выше 0 снимает «недееспособен» (`quickHealthClearsIncapacitated`), «повержен» не трогает.
Прочие правки Здоровья статус не снимают (снимают проверка после боя, «Получил помощь» и смерть). Подсказки
по наведению на листе нет: правая кнопка на иконке или подписи «Здоровье», на «Защите» и на «Боевом
духе» держит нашу подсказку (как вводить Здоровье; что даёт Защита и включена ли; порог и попытки
теста), левый клик — действие. Режим редактирования — кнопка героя: поля для всего хранимого (имя, картинка,
фракция, уровень, «легендарное», характеристики, Боевой дух, Дикая мораль, теги списком с
удалением и пустой строкой для нового, эпик-таблица, Описание). Пустые теги при сохранении
отбрасываются.

**Стрелки (реализация).** У существа с тегом «Стрелок» (26 существ) на листе две кнопки атаки:
«Ближняя» — с эпик-таблицей существа, как у всех; «Дальняя» — без художественной строки, но
существенность и «Куда попал» бросаются, как у стрелкового оружия героя (§5.4). В карточке
чата указано, какая была атака. У остальных существ одна кнопка. Существа, которые стреляют без
тега (Матрос, Головорез, Нимфы, Элементали Воды — выстрел только в строках ближней
эпик-таблицы), не трогаются: книга дала им лишь ближнюю таблицу. Выбор ветки — чистая
функция `resolveAttackEpicTable` (`module/helpers/rolls.mjs`).

## 10. Что нужно автоматизировать

Приоритет по убыванию:

1. **Атака по клику** — d6 по таблице, d20 против `Защита − Атака`, множитель, вывод в чат
2. **Инициатива** — d20 + Скорость
3. **Мана** — расчёт максимума от Знаний с учётом Интеллекта, списание при касте
4. **Заклинание** — показ варианта по уровню навыка школы, списание нужной стоимости
5. **Эпик** — бросок по таблице оружия/существа, повторный d6, «куда попал»
6. **Боевой дух** — тест d6 на повтор хода
7. **Небоевая проверка** — d20 + бонус против сложности

Не автоматизируем на первом этапе: перемещение по клеткам, области заклинаний, доспехи и их разрушение, отслеживание длительностей.

Открытые пункты (найдены при автоматизации навыков, не сделаны):
- Артефакты, выдающие или поднимающие вторичный навык («Золотой лук», стр. 46; «Колье
  неприступности», «Амулет гробовщика», стр. 49) — уровень навыка берётся только из
  предмета-навыка, артефакт его не меняет.
- Каст заклинаний не выбирает цели и не наносит урон/эффекты — кроме пяти заклинаний прямого урона
  этапа 1, пяти усилений/ослаблений этапа 2, десяти заклинаний группы А1, пяти группы А2, трёх
  группы В, трёх «в поле зрения» шага 4, четырёх «Выберите клетку» шага 5, четырёх группы Г с экспертным Развеиванием по клетке и двух группы Д (§6.4);
  остальное применяет Ведущий вручную.
- Известные ограничения ядра (не чиним, решение Сени): Зыбучий Песок, если Ведущего нет в сети, —
  клиент игрока останавливает токен на границе ловушки, но открыть её, написать строку в чат и
  поставить токен в клетку некому (это делает активный Ведущий), и после его возвращения это не
  происходит; движение, упёршееся в Силовое Поле, останавливается там, где путь касается поля, не
  по сетке — как у стен ядра.
- Артефакты, снижающие Боевой дух противника («Кулон разорения», стр. 49; «Кольцо
  подавления», стр. 51), не автоматизированы — Ведущий правит поле Боевого духа существа
  (или поправку героя) руками.
### Сообщения в чате: кому видно и как свёрнуто (реализация)

**Видимость.** Режим в Foundry v14 — опция `messageMode` при создании сообщения (или явный
`whisper`); `core.rollMode` устарел. Выпадающий список режима в строке чата — настройка
каждого клиента, мировой настройки у Ведущего нет. Ведущий видит шёпот, только если он в
списке получателей.
- Атака: уважает выпадающий список; «только себе» поднимается до «владельцы атакующего +
  Ведущий», иначе Ведущий не смог бы подтвердить урон.
- Проверка навыка, макрос предмета с хотбара: уважают выпадающий список (как core
  `Roll#toMessage`).
- Броски повышения уровня (первичный навык, новый вторичный): шёпот владельцам героя и
  Ведущему.
- Каст (все карточки: обычная, урон, усиление): как атака — уважает выпадающий список, «только
  себе» поднимается до «владельцы кастующего + Ведущий»; приватная — без `rolls`.
- Убийство недееспособного, Боевой дух, проверка после боя / «получил помощь»: публично.

Приватная карточка атаки и броски повышения уровня уходят **без `rolls`** (число куба уже в
тексте карточки): Foundry показывает не-получателям шёпота с бросками заглушку «бросает
скрыто» (`ChatMessage#visible` для броска всегда true). Проверка навыка в приватном режиме
`rolls` сохраняет — поведение как у core.

**Компактность.** Сворачиваются только карточки атаки и каста — остальные и так в 1–2
строки. По умолчанию свёрнуто; переключатель — заголовок карточки (▸/▾). В заголовке атаки:
исход и урон, отступление при эпике, «Куда попал» с последствием, разрушение доспеха,
предупреждение Ведущему, кнопка «Подтвердить»/«Применено»; в подробностях — оружие, кубы с
кнопками переброса за Удачу, множители, эпик-таблица. У каста в подробностях — школа,
стоимость и остаток Маны. Состояние раскрытия — в памяти клиента: переживает перерисовку
карточки (подтверждение, переброс), сбрасывается при перезагрузке страницы. Карточки,
созданные до этого изменения, остаются в старой плоской разметке, пока их не перерисует
подтверждение или переброс.
